## Vision

### 10x Check
The 10x version transforms MyLife from "Microsoft Office of Personal Apps" into "the Personal Data Operating System." The hub IS the intelligence layer. Modules are data sources, but the real product is the cross-module insight engine that does things no individual app can do. On-device AI with per-module privacy permissions. Automated cross-module workflows. A unified personal data dashboard with AI-generated narrative summaries. Data portability as a weapon against enshittification. A legally binding Anti-Enshittification Pledge.

### Platonic Ideal
Opening the app feels like opening a journal that knows you. Your dashboard is YOUR day -- fasting timer running, next medication in 2 hours, 3 chapters left in your book. Periodic privacy transparency: "Your cycle data has been stored locally for 365 days. It has never left your device." Cross-module insights feel like having a personal data scientist: "Your mood scores are 23% higher on days you fast 16+ hours AND exercise." You can export everything, delete everything, self-host. You're not trapped. And because you're not trapped, you choose to stay.

## Expansion 13: Biometric Human Verification (added during Eng Review)

**Decision: ACCEPTED**

Social features (Forums, Market) require proof-of-humanity via biometric authentication. Uses Apple Face ID / Touch ID and Android BiometricPrompt. App NEVER receives biometric data -- only a boolean confirmation from the OS Secure Enclave.

**Architecture:**
- `hub_human_verification` table: user_id, verified_at, method, device_attestation_token
- Gates: Forum posting, Market listing, any social write action
- Read-only browsing: allowed without verification
- Mobile: LAContext (iOS) / BiometricPrompt (Android)
- Web: Verify on mobile first, sync verified status to web session. WebAuthn/Passkeys as alternative.
- Fallback: device passcode (weaker but still device-bound)

**Data sharing philosophy:**
- All social data sharing is explicit opt-in
- Users select WHICH data is shared
- All shared data is anonymized
- We do not sell shared data
- Users can delete their shared data via a button in Settings
- Periodic reminders: "You're sharing X data. Want to review?"

- All social data sharing is opt-in, anonymized, never sold, deletable on request

## Architecture Additions

### New Packages Required
1. **packages/intelligence** -- Cross-module query engine, per-module access permissions, correlation engine (generalized Pearson), on-device inference adapter
2. **packages/search** -- Unified FTS5 index across all module tables, result normalization
3. **packages/onboarding** -- First-run flow state machine, content preferences, module selection, import wizard registry
4. **packages/engagement** -- Weekly digest aggregation, life engagement streak, "This Day Last Year"

### AI Permission Architecture
- `hub_ai_permissions` table: module_id, enabled (boolean), granular_mode (boolean)
- `hub_ai_table_permissions` table: module_id, table_name, enabled (boolean) -- only consulted when granular_mode = true
- Default: all modules OFF. Users opt-in during onboarding or settings.

### Onboarding Flow
```
START -> WELCOME (privacy pledge) -> CONTENT_PREFERENCES (filtering) ->
MODULE_SELECTION ("What matters to you?") -> IMPORT_WIZARD (per-competitor) ->
AI_PREFERENCES (optional) -> DASHBOARD_REVEAL (personalized)
```

## Critical Gaps (must fix before launch)
1. **habits migration:** V2 references non-existent period_id column -- blocks fresh installs
2. **garden migration:** references non-existent status column -- blocks fresh installs
3. **No SQLite backup mechanism** -- total data loss on corruption
4. **CSV import fails silently** -- no user feedback on parse errors
5. **~12 web modules are fallback stubs** -- must build or hide before launch

## Security Decisions
- AI cloud inference: on-device statistical by default. User-provided API key for LLM opt-in with explicit transparency warning.
- All local modules: zero cloud exposure
- Cloud modules (Forums, Market, Surf, Workouts, Homes): Supabase RLS + TLS
