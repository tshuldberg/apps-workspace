## Problem Statement

MyLife currently has 29 modules consolidating privacy-first personal apps into a single hub at $5/yr. The bundle thesis works -- people react with "that's too ambitious" and then say "if I saw that app I'd buy it." One person literally gave $5 as a deposit. The goal is to maximize the number of high-quality modules to make the "47 apps for $5/yr" headline real. More modules = more reasons to download = more conversion moments.

## Demand Evidence

- Multiple named users want specific modules: Cycle (privacy-first period tracking), Recipes + Workouts + Nutrition (cross-module fitness), Facebook Marketplace alternative, Screen Time / Social Lock (user currently pays >$5/yr for this alone)
- Surfline, Strava, and AllTrails users have expressed intent to switch for the privacy + price story
- Universal reaction: "too ambitious but I'd buy it" -- the ambition IS the conversion mechanism
- One person gave $5 and said "call it a deposit"
- Competitive research shows $2.3B+ in annual revenue across the top 8 existing module categories alone

## Status Quo

Users currently pay $400+/yr across 6-8 separate subscription apps, each harvesting their data. There is no privacy-first hub that bundles personal utility apps. The closest analogs (Apple's built-in apps) are free but shallow and data-connected to Apple's ecosystem. No one has attempted 47+ categories in a single app.

## Target User & Narrowest Wedge

**Primary:** Privacy-conscious iPhone user (25-45) who subscribes to 3+ personal utility apps and is tired of subscription fatigue + data harvesting. They'd switch if one app replaced all of them for $5/yr.

**Wedge:** The "47 apps for $5/yr" headline itself. The sheer volume of categories covered is the conversion event. Show someone the app, let them scroll through 47 modules, and the reaction converts from "that's impossible" to "take my money."

## Constraints

- All new modules must follow the existing ModuleDefinition contract
- SQLite-first, offline-first, zero telemetry, zero ads
- Each module must justify its existence as a standalone app someone would pay for
- Privacy is co-equal with price as the value proposition
- Cross-module data correlation is the long-term moat
- Build difficulty must be manageable: skip complexity 5 modules for now

## Premises

1. Every high-user-count personal utility app is a potential MyLife module. The bundle strategy wins on breadth, not depth.
2. Build difficulty matters more than market size for prioritization -- a module that takes a weekend beats one that takes a month.
3. The $5/yr price against $30-100/yr competitors is the primary user acquisition lever. Privacy is co-equal.
4. Cross-module data correlation is the moat that prevents single-category apps from competing.
5. The "too ambitious" reaction IS the marketing -- showing it actually works is the conversion moment.
6. Zero tracking, zero ads, encryption by default. This is a trust product.

## Approaches Considered

### Approach A: Rapid Fire 10
Build the 10 easiest high-impact modules (Water, Focus, Expense Split, Body, Gratitude, Wishlist, Chore, Savings Goals, Sobriety, Tasks). All complexity 1-2. Adds ~280M addressable users. Ships fast but stops at 39 modules.

### Approach B: Privacy Fortress
Prioritize 9 modules where privacy is the #1 switching motivation (Password Vault, Photo Vault, Screen Time, Contacts CRM, Calendar, Scan, Baby, Dream, Net Worth). Slower but deepens trust thesis.

### Approach C: 39 Module Blitz (CHOSEN)
Build 15 new standalone modules (complexity 1-3) and absorb 6 features into existing modules in Sprint 1 (29->44). Sprint 2 adds 6+ more from complexity 3-4 to reach 50+.

*Photo Vault revised to complexity 3 (encryption at rest, secure key management, biometric unlock). Screen Time revised to complexity 3 (iOS Family Controls entitlement required).*

**Complexity scale:**
- 1 = Pure CRUD + timer/counter. No external APIs, no hardware, no permissions. (Water, Body, Focus, Expense Split, Wishlist, Gratitude, Chore)
- 2 = CRUD + HealthKit or Contacts framework integration, or multi-screen flows. (Tasks, Travel, Baby, Sleep, Routine, Contacts)
- 3 = Encryption, system extension, or restricted API entitlement. (Photo Vault, Screen Time)
- 4 = Real-time audio/sensor analysis or external content APIs.
- 5 = Hardware dependency or marketplace requiring critical mass.

**Features absorbed into existing modules (not standalone):**
- Savings Goals -> Budget (visual savings jars, goal progress bars)
- EV/Fuel -> Car (charging station finder, fuel economy log)
- Breathe -> Habits (breathing exercises via existing timed sessions engine)
- Home Inventory -> Homes (room-by-room possession tracker)
- Sobriety -> Habits (sobriety engine already exists: `sobriety/engine.ts`, `craving-engine.ts`, `milestones/engine.ts`)
- Dream -> Journal (dream journal entries with pattern tags)

**Result: 15 net-new standalone modules + 6 absorbed features = 29 + 15 = 44 standalone modules.**

**Tier assignment:** All new modules are premium (require MyLife Pro). Free tier remains: `fast`, `forums`, `journal`, `market`, `mood`, `notes`, `voice`.

## Open Questions

1. Should Sleep be a standalone module or absorbed into Health? (Recommendation: standalone -- sleep apps are a $30+M category)
2. Should Screen Time use the iOS Screen Time API or build a parallel tracking system? (Recommendation: iOS API + our own tracking for cross-module correlation)
3. Password Vault autofill requires an iOS credential provider extension. Is this worth the complexity? (Recommendation: yes, in Sprint 2)
4. Should we build Tasks or integrate with Reminders.app via EventKit? (Recommendation: standalone for privacy, but import from Reminders as onboarding)
