1What DoWork Is

DoWork is the standalone surface of the MyLife workouts module, repositioned by Plan 36 as an invite-only trainer platform: a $4.99 paid workout tracker for lifters, with a trainer directory, a Trainer Studio with signed video uploads, a private coach-client form-check loop, a hands-free voice-controlled player, RevenueCat trainer subscriptions, push notifications, and honest offline downloads. Local training data lives in dowork.db (SQLite, wk_* tables); everything social and monetized lives in its own Supabase project (dw_* tables + 6 edge functions), with entitlement enforced server-side.

⚠ Read this first - the two code lines
There are currently two DoWork states. main carries Plan 36 Phases 1–7 plus the founder-ops execution. But the 2026-07-04 dp-audit fix wave - 11 commits, 22 findings fixed, 2 new migrations, plus a whole new reset-password.tsx screen - lives only on the unmerged feature/dowork-trainer-launch branch (verified: git merge-base --is-ancestor says NOT merged; 54 files / +2,650 −765 diff vs main). Several issues this report flags on the reviewed tree are already fixed there and are tagged FIXED ON BRANCH. The single highest-leverage action from this whole review: merge that branch.

Verdict - one token file, two visual dialects
The token layer itself is clean: one file, semantic names, WK re-exports so hub and standalone can't drift on typography or category color. But the screens split into two visual generations. The Plan 36 trainer/account/notification screens use DW_TEXT faithfully. The screens ported from the hub in April (most tools, social, parts of the session flow) still carry the hub's Obsidian palette - #131318 surfaces, #E4E1E9 titles, tan #D6C3B5 secondary text - and the social screens hardcode that beige directly. Two "secondary text" colors and two surface stacks coexist in one app. The 2026-07-04 readiness report itself lists "two-brand visual seams" as a known deferred item. A one-day sed-style sweep of #E4E1E9 → DW_TEXT.primary, #D6C3B5 → DW_TEXT.secondary, #131318 → DW_SURFACES would unify the app.

4The Three Users

Every screen in DoWork serves one of three overlapping roles. The same binary morphs around a single cloud row (dw_trainers) and a single RPC-joined relationship (dw_client_links) - there is no separate "trainer app".

Persona 1 · The Lifter (everyone)

Buys the $4.99 app, gets the full solo tracker forever: builder, live session engine, 400+ exercise library, programs, AI generation, 1RM/plates/calculators, GPS cardio, recovery heatmap, insights, photos, measurements. All local in dowork.db - works with the cloud completely off. Anonymous Supabase session is created silently for social/coaching later.

Persona 2 · The Fan / Client

Discovers a trainer in the directory, watches free videos, hits the paywall on premium ones, subscribes at the trainer's tier price (RevenueCat, 8-tier ladder). Or joins as a coaching client via a QR/12-char invite code - which grants premium access without a subscription (the 4th entitlement path) - then sends form-check videos and gets timestamped feedback.

Persona 3 · The Trainer (invite-only)

Redeems a service-role-minted invite code, which creates the dw_trainers row - the only creation path. Gets the Studio: profile editor, signed video upload pipeline (10 min / 500 MB caps), publish/premium toggles, client roster with QR invites, form-check review queue, and an earnings screen fed by the dw_get_trainer_earnings RPC (never the raw purchase ledger).

6Core Training Flow

The solo-lifter half of the app: build → session → save → share. Driven by the @mylife/workouts player engine, a reducer with states idle → playing ⇄ paused, rest, and completed, advanced by START / PAUSE / RESUME / COMPLETE_SET / TICK / SKIP_EXERCISE / PREVIOUS_EXERCISE / ADJUST_REST / REST_COMPLETE.

🚨 Critical - the live session boots dead (verified twice)
session.tsx:240 initializes the player with createPlayerStatus(), which starts in idle (engine.ts:44) - and no code path ever dispatches START. In idle: the Mark Complete button is disabled (:874, requires playing), the Pause/Resume toggle renders neither button (:853 renders null unless playing/paused), and the tick interval never starts. RESUME can't escape idle (engine only allows it from paused). Net effect: a user who starts any workout cannot log a single set. Verified in the working tree AND on feature/dowork-trainer-launch. It survived 322 app tests (they cover data modules, not this screen) and both audits (cloud-focused) because no installable build has ever run. One-line fix: dispatch START after setup (or add an explicit "Start Workout" button that does). Found independently by gpt-5.5 and confirmed by direct code read.
