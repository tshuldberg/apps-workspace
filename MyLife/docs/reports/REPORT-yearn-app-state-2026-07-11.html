3 · User workflows as implemented

First run to browsing

Install → open→ Age gate (18+, persisted)→ Sign in (Apple / Google / email link / SMS, PKCE)→ Restoring session→ Checking profile→ 10-step onboarding (draft survives kill)→ Discover deck

On sign-in the app also publishes this device's E2EE public key to the key directory. Returning users with a profile skip straight to the deck; the persisted birthdate pre-fills onboarding.

Like, match, chat (E2EE)

Like on deck→ Optional encrypted intro note→ Recipient sees it under Likes→ Like back (match cap enforced)→ Match + realtime E2EE chat
Sender key changes→ Messages hidden + warning→ "Verify with them outside Yearn, then press Send again to trust the new key."

Safety

Report (Harassment / Fake profile / Underage / Sexual content)→ Row written server-side→ No moderation action path yet (launch blocker, see 5.4)
Block→ Mutual exclusion from decks, likes, matches (RPCs re-check is_blocked)

Boost (current, after plan 50)

Deck UI→ No Boost button; copy: "Boost isn't available yet"
Direct RPC attempt (attacker)→ activate_boost DROPPED; boosts table has no client write path
Future purchase → edge fn→ JWT sub + transactionId→ App Store Server API verify (prod → sandbox)→ bundle/product/Consumable/no-revocation/id-echo checks→ grant_boost (service-role, one redemption per tx, YB409 on cross-user replay)
Apple credentials unset (today)→ 503 boost_unavailable, fail closed: "Boost isn't available yet. No boost was activated..."

Account deletion

You → Delete account→ "Tap again to permanently delete"→ delete_my_account purges; boosts cascade on user delete
