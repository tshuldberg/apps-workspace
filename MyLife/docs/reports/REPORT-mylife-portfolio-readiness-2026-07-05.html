MyLife Portfolio Customer-Readiness Ruling

2026-07-05 · 8 product surfaces + 41 registry modules (full per-module table in Appendix A) · 8 parallel adversarial auditors, final ruling by synthesizer · HEAD fbef9997, branch feature/meerkat-launch-completion
Standard: a stranger can find, install or load, pay for, and successfully use the product today, with the legal and safety obligations of its category met.
Final ruling: 0 of 8 products are GO today. All 8 are NO-GO.

Engineering quality is high and the honesty discipline (fail-closed, no fake connectivity, no fabricated status) held almost everywhere. What is missing is the commercial shell: billing, deployment, distribution, legal, and trust-and-safety. Two products also carry product-breaking code defects (DoWork, BestChef).

The single most important portfolio-wide fact: there is currently no configuration in which any customer can pay you. packages/entitlements/src/test-mode.ts hardcodes _testMode = true (everything free), and no payment SDK is installed in hub mobile, hub web, Meerkat, or BestChef. Only DoWork and Manhattan have real, guarded billing code paths, both waiting on RevenueCat products that do not exist yet.

Verified on main, the launch branch, and the current checkout.

Correction: yesterday's C2 (unmerged 11-commit fix wave) is stale. The wave is fully merged via d8070864. Closed.

Everything else is founder-ops: RC products + keys (the pre-install guard correctly refuses production builds without them), ASC id still REPLACE_WITH_ASC_APP_ID, legal drafted but unhosted, push keys, icon, device white-glove QA. Supabase prod is live and verified; the 8-tier trainer ladder is real.

  • 1. Dispatch START on session mount + regression test (under a day). This alone restores the product.
  • 2. Honesty triage: Home fake volume, streak math, body-map mapping, generator-ignores-equipment (0.5-1.5 days).
  • 3. Founder-ops F3 (RC, unblocks builds), F2 (ASC), F5 (host legal), F6, F8, then F7 device QA and submit.

2Manhattan NO-GO to submit CODE IS GO

The only product where every blocker is external to the code. Paywall fails closed by construction (test mode compile-time impossible in production, launch-environment.ts:96-102); a pre-install guard hard-fails builds missing RC keys (check-build-env.mjs:33-53); undeployed sources return empty, never fake (NYC Open Data works with zero setup). 5Meerkat NO-GO

Three independent fatal walls, all confirmed:

  • Cannot connect. DEFAULT_RELAY_URL='' and nothing is deployed (relay, community node, directory, TURN). Two strangers cannot exchange a single byte. Deliberate honesty, but the product does not exist for customers yet.

6MyLife Hub (web) NO-GO as a hosted product

Builds (478 pages) but is hosted nowhere, has no deploy config, and its data layer is one better-sqlite3 file at process.cwd() shared by all visitors, with a developer's live DB committed to the repo (apps/web/mylife-hub.db*). No multi-tenancy in default modes. Stripe not a dependency; checkout throws "Stripe not initialized" once test mode stops shielding it. Legal routes and account deletion do exist and lead the other surfaces.

Decision required first: self-host single-user (~1-2 weeks to package honestly) vs hosted multi-tenant SaaS (per-user server DB + RLS + auth + deploy, ~4-8 weeks). Recommendation per the full-function mandate: the hosted path, sequenced after the mobile products that are days-to-weeks from revenue.

7BestChef NO-GO confirming today's world-launch audit

All five CRITs re-verified live in code today, unchanged since the audit commit:

  • CRIT-1 Public builds feed SAMPLE_GROCERY_PHOTO_JSON into recognition when no BYO key exists (kitchen-photo.tsx:42,107 → kitchen.ts:1492-1494): real users get fake "Organic Milk" and "Bananas" in their pantry. The most serious honesty breach in the portfolio.
  • CRIT-2 Empty-ingredient submissions render hardcoded Pad Thai, ungated by demo policy (recipe/[id].tsx:382-389).
  • CRIT-3 $0 monetization vs live AI + video-egress costs; tips/subs fabricate pi_/sub_ ids via Date.now() with zero UI callers.
  • CRIT-4 No CSAM/NCMEC; world-readable pre-moderation bucket; no GDPR export.
  • CRIT-5 Key-only i18n gate passes ~1,155 byte-identical English values across 21 catalogs as "100% parity."

BestChef has the most distribution progress (TestFlight build 24) and green gates, which is the trap: the gates do not measure what blocks launch. Path: fix CRIT-1/2 + value-identity i18n gate immediately (hours), then Tier 0 safety/legal (~6-8 wks, vendor), Tier 1 first wave (~6-8 wks), Tier 2 business model (~3-5 wks). First public wave realistically ~3+ months.

8Yearn NO-GO · HARD STOP

Crypto and DB provisioning are genuinely done, and that is the trap: the missing part is the legally non-negotiable trust-and-safety spine for a dating app.

  • CRIT No CSAM detection or NCMEC pipeline anywhere; user photos stored + served with no scan (statutory duty, 18 U.S.C. 2258A).
  • CRIT Reports write to a table nobody reads: no moderation queue, admin surface, SLA, or action model.
  • HIGH Cannot report/block a matched user (safety controls exist only pre-match); chat has no realtime and no polling (non-functional as a messenger); location permission requested but never used (rejection risk); no EAS project or ASC record.

Path, safety first: CSAM scan on upload + NCMEC → moderation queue + SLA → in-chat report/block → realtime chat → real geo or drop the permission → eas init + ASC + push + legal. Do not distribute, including external TestFlight, before the first three exist.

Part 3 · Systemic Findings

  1. S1. Revenue is impossible portfolio-wide. Hardcoded _testMode = true plus no payment SDK in hub mobile/web, Meerkat, BestChef. Only DoWork and Manhattan have real billing code, both blocked on RC products that take about an hour to create. Fastest path to first revenue in the portfolio: create RC products for DoWork, fix the START bug, ship.
  2. S2. Legal corpus debt everywhere. Only DoWork has drafted (unhosted) docs; hub web has in-app legal routes. Every store submission blocks on this. One legal-writing pass can serve all products.
  3. S3. Trust-and-safety is one shared hole. BestChef, Yearn, Meerkat public layer, and MyNews UGC all need the same missing spine: CSAM hash-matching, NCMEC reporting, human moderation loop. Procure once, build one shared intake pipeline, reuse across all four. Vendor lead time is the longest pole in the portfolio; start procurement now.
  4. S4. Distribution debt. Only BestChef ever produced a store-track build. EAS projects: hub, Meerkat, DoWork yes; Manhattan, Yearn, MyNews no. ASC: hub 6761207231; Manhattan and MyNews claim the same 6763167108 (at least one wrong); DoWork placeholder; Yearn none. No web surface is deployed anywhere.
  5. S5. Honesty discipline mostly held, one bad exception. Meerkat, Manhattan, MyNews, and the module fleet fail closed consistently. BestChef is the outlier (sample fixtures reaching real users). Make it a repo-wide gate: no SAMPLE_* constant may be reachable when the demo policy is off.
  6. S6. Same-day docs were already stale; code was the only reliable source. DoWork C2 was already merged; MyNews editing desk already on main; CLAUDE.md counts behind. Re-verify in code before every launch decision.
