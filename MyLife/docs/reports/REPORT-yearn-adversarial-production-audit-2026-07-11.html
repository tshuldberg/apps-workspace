Critical & High — Security / E2EE

Y1 Critical — Sender-key binding is dead code on receive. YearnSocialSurfaces.tsx:492-496 passes only senderUserId, never senderPublicKey, so the attacker-authored key inside the envelope is trusted. A match partner or rogue device can impersonate with no key-change warning — the exact surface the prior F2 fix closed, silently regressed (send path pins keys, receive path doesn't).

Y3 High — PKCE flow not configured. supabase.ts sets no flowType → supabase-js defaults to implicit, but authLinks.ts calls exchangeCodeForSession. Google OAuth and ?code= magic links fail. OAuth sign-in is broken.

Y4 High — No CSPRNG polyfill. The crypto shim throws if globalThis.crypto.getRandomValues is absent; nothing imports react-native-get-random-values or sets nacl.setPRNG at entry. Under Hermes, every E2EE encrypt may throw on first use. Vitest masks it.

Y2 High — Multi-device broken. Directory returns one device (limit 1); pairwise nacl.box rejects other devices → second device / reinstall renders all prior ciphertext null.
