What the app is right now

MyLife is a single Expo app (iOS + Android) plus a Next.js web app. A hub dashboard hosts privacy-first life modules that the user enables individually. All standard modules share one local SQLite file with per-module table prefixes; three modules use cloud backends (surf and workouts on Supabase, homes on Drizzle + tRPC). There is no analytics or telemetry. Auth is optional: a local-only provider is the default and cloud accounts are only needed for the cloud modules.

Local-first privacy model

APP

Local SQLite is the default store

DatabaseProvider opens a single on-device SQLite file before anything else mounts; 36 of 38 wired modules are sqlite-backed with their own table prefix (surf and workouts use Supabase, homes uses Drizzle).

USER

Auth is optional, not required

_layout.tsx wraps the tree in LocalAuthBridge -> LocalAuthProvider(db) always, then an outer AuthProvider whose Supabase-backed AuthService is only constructed when EXPO_PUBLIC_SUPABASE_URL/ANON_KEY env vars are present; without them authService is null and the app runs on local-only auth. (auth)/sign-in.tsx and sign-up.tsx both call useLocalAuth(), not the Supabase service.

USER

Per-module PIN locks

(hub)/module-locks.tsx lets the user set a 4-6 digit PIN per lockable module (verified via verifyPin/enableModuleLock/disableModuleLock from @mylife/auth); this gates viewing a module's content on-device, separate from any subscription state.

USER

Backup, export, self-host

(hub)/backup.tsx, (hub)/self-host.tsx and per-module export screens (e.g. books/export, budget/export-data) give the user device-side control over their data without a mandatory server round-trip.

Premium unlock (current state) - honest dead end

USER

Tap a locked premium module card

components/ModuleCard.tsx: for tier==='premium' modules where useModuleUnlocked(module.id) is false, tapping the card does not navigate; it opens a pageSheet Modal containing PurchaseGate instead of the module route.

APP

PurchaseGate renders two real-looking purchase buttons

components/PurchaseGate.tsx shows "Unlock All Modules $19.99" (hub) and "Unlock {ModuleName} $4.99" (standalone), prices sourced from @mylife/billing-config PRODUCTS, plus a "Restore Purchases" link.

USER

Tap either purchase button

handlePurchase calls paymentService.purchase(productId), which on mobile routes through routeMobilePurchase -> rcPurchaseHub()/rcPurchaseStandalone() in packages/subscription/src/revenuecat.ts.

APP

RevenueCat SDK is never initialized

apps/mobile/app/_layout.tsx calls createPaymentService({ platform: 'mobile' }) with no revenueCatApiKey and no revenueCatSdk. service.ts only calls initRevenueCat(sdk, apiKey) when both are present in config, so on mobile today neither runs.

APP

getSDK() throws, surfaced as an error string

revenuecat.ts getSDK() throws "RevenueCat not initialized. Call initRevenueCat() first." purchaseHubUnlock/purchaseStandaloneModule catch this and return { success: false, error: String(err) }, which PurchaseGate renders directly under the buttons as red error text.

FOUNDER

Net effect: every premium module is a real-looking dead end

The UI (lock overlay, PRO badge, PurchaseGate modal, priced buttons) is fully built and honest about intent, but no purchase can complete on mobile until a RevenueCat API key and SDK instance are wired into _layout.tsx's createPaymentService call. Web's Stripe path is separately configured via stripeSdk and is not affected by this gap.
