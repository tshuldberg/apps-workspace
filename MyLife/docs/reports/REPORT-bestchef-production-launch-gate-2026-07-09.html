Critical blockers

Any one of these is enough to stop launch. All ten are open.

C1

Configured production backend is inactive and unreachable

10/10 verified

EAS production points at zjxabnazbdocrqpyixgo. Supabase reports that project INACTIVE; its API host does not resolve and migration listing times out. The live production smoke suite is skipped by default at testflight-smoke.live.test.ts:78.

Closure: restore or replace production, prove DNS and database health, apply every migration, then run the full live suite against the exact release environment.

C2

No production binary contains the reviewed code

10/10 verified

Latest store build is EAS build 24 at 8a65bc8c, created May 12. Reviewed source is d3caa1fe, 58 scoped commits and 314 changed files later. Public App Store lookup for ID 6763167108 returns zero results.

Closure: create a new IPA from the approved SHA and bind every test to its EAS ID and commit.

C3

Deployed Edge Function fleet is stale, incomplete, and misconfigured

10/10 verified

Seven hosted v3 functions were last updated April 29. bestchef-media-purge is absent. Hosted moderation and deletion workers have verify_jwt=true, while supabase/config.toml:418-432 requires false for worker-secret calls.

Closure: deploy all eight functions from one SHA and assert versions, hashes, secrets, and JWT flags after deploy.

C4

CookProof moderation is a hardcoded approval stub

10/10 verified

moderate_vote_proof/index.ts:454-505 returns NSFW 0.02, food 0.91, and available true. Approval thresholds are 0.72 and 0.55. The live Deno handler always injects these stubs at :694-711.

Attack path: upload any image as vote proof, invoke the worker, receive fixed safe scores, activate the vote, and mark the asset public without byte inspection.

Closure: real providers, fail-closed outage handling, adversarial corpus, and a deploy guard that rejects stub providers.

C5

General media moderation and CSAM handling do not exist

10/10 verified

20260529000004_bestchef_media_moderation_enqueue.sql:8-10 describes a future worker for media assets and CSAM checks. No implementation or schedule exists. Repository-wide runtime search found no hash matching, escalation, preservation, or reporting integration.

Closure: complete the worker, quarantine, human review, lawful reporting, preservation, and incident drills with specialist review.

C6

Submission images are anonymously public before moderation

10/10 verified

Migration marks the bucket public, storage policy grants anonymous SELECT, and local migrated state confirms both. submission-photo.ts:170-216 returns getPublicUrl() immediately after finalize.

Attack path: upload prohibited media, receive its public URL before review, then distribute it directly.

Closure: private buckets, owner-only previews, approved derivatives, and a policy test proving anonymous pending reads fail.

C7

Account deletion fails open and announces success

10/10 verified

data/account.ts:213-249 turns cloud failures into warnings. It then wipes local files, rows, and secrets unconditionally at :252-254. Settings always displays Account deleted at settings.tsx:210-220.

Closure: durable server receipt, recoverable retry, truthful states, and failure-path tests before local destruction.

C8

Grocery-photo recognition fabricates sample groceries

10/10 verified

kitchen-photo.tsx:42 initializes sample JSON. Real photo selection clears it only when a BYO key exists, but public launch disables BYO keys. data/kitchen.ts:1488-1499 prioritizes the sample JSON over the broker.

Closure: remove production samples, require a real broker response or honest failure, and add a public-build regression test.

C9

Empty recipes become an unrelated Pad Thai recipe

10/10 verified

recipe/[id].tsx:128-151 defines Pad Thai samples. Empty ingredients or steps receive those arrays without a demo guard at :382-389. That false content can drive allergens, nutrition, and grocery additions.

Closure: honest missing states, no synthesized fields, and blocked downstream derivation without source data.

C10

Legal, support, and policy claims are not launchable

10/10 technical

The app hardcodes five bestchef.app routes, but the domain does not resolve. Terms and privacy retain operator, date, region, and venue placeholders. They also claim automated screening and contracted providers that do not exist in current code.

Closure: counsel-finalized copy tied to implemented behavior, live durable routes, staffed support, and server-side terms receipts.

Security posture

Attack surface

  • 5 user-authenticated Edge Functions
  • 3 worker-secret Edge Functions
  • Public PostgREST and Storage controlled by RLS and bucket policy
  • iOS photo and video UGC with offline SQLite cache
  • Service-role moderator console
  • Supabase, Anthropic, Open Food Facts, USDA, and planned GS1/commerce integrations

Verified attacker findings

  1. Critical: fixed safe scores approve arbitrary CookProof media.
  2. Critical: pending submission images are anonymously readable.
  3. High: non-atomic claims permit duplicate or racing moderation decisions.
Not found: no current high-confidence credential pattern in BestChef source; broad history-prefix hits did not match real key formats. Main CI actions are SHA-pinned. This pass does not replace an independent mobile penetration test or specialist public-UGC safety assessment.

Required resolution plan

Everything below ships together before launch. The order reflects dependency, not a later phase.

A

Restore and prove production

Make the actual server plane current, observable, and recoverable.

  1. Reactivate or provision the named production Supabase project with owned naming and access.
  2. Apply and reconcile the full migration ledger through a clean staging clone.
  3. Deploy all eight functions from one SHA and verify hashes, secrets, versions, and JWT flags.
  4. Configure and schedule ranking, deletion, action-prune, moderation, and purge jobs.
  5. Repair job health, then run deletion, storage, RLS, quota, recovery, and moderation drills.
  6. Configure backups, point-in-time recovery, restore drills, logs, alerts, dashboards, and on-call.
Exit: healthy DNS and database, migration parity, SHA-bound function manifest, full job health, successful restore, and 48 hours of healthy telemetry.
B

Make public UGC safe and supportable

Replace safety theater with real prevention, review, and response.

  1. Real NSFW, food, face, and illegal-content providers with fail-closed behavior.
  2. Complete general media worker, quarantine, human escalation, preservation, appeals, and lawful reporting.
  3. Private pending buckets and approved sanitized derivatives only.
  4. Atomic moderation claims and idempotent decisions.
  5. Production console with MFA, least privilege, audit retention, SLA, and emergency removal.
  6. Counsel-finalized legal corpus tied to the implementation.
  7. Live legal and support domain with tested intake and response.
Exit: adversarial corpus, zero anonymous pending reads, concurrency proof, moderator drill, counsel signoff, and live matching legal routes.
C

Remove fabricated and destructive behavior

User data must be true, recoverable, and complete.

  1. Remove grocery and recipe sample defaults from production.
  2. Require source data for nutrition, allergens, grocery items, and steps.
  3. Deletion requires a durable server receipt and recoverable retry.
  4. Complete server-side account export with all cloud data and media manifests.
  5. Authoritative challenge metrics with surfaced errors.
  6. Visible retry and failure states across home, feed, profile, and ranking.
Exit: failure-branch regression suite, deletion and export drills, seeded challenge proof, and zero silent cloud failures in the launch matrix.
D

Complete every advertised workflow

No placeholders, fake processor IDs, or English values hidden behind green gates.

  1. Remove every reachable /soon destination and connect real Recipe, Video, Capture, and Cook flows.
  2. Connect Cook mode to real recipes without fallback steps.
  3. Camera barcode, licensed food data, grocery delivery, checkout, and full recipe import.
  4. Complete push registration, delivery, preferences, localization, deep links, and cleanup.
  5. Video transcode, metadata sanitization, adaptive playback, CDN authorization, and revocation.
  6. Real StoreKit and processor payments, subscriptions, tips, receipts, refunds, entitlements, and payouts, or remove all related claims.
  7. Translate and professionally review all advertised catalogs, with value-aware gates.
Exit: no placeholder routes, full workflow E2E, provider and payment proofs, push matrix, video load test, and native-language signoff.
E

Produce a release that can be signed

One artifact, one SHA, one evidence packet.

  1. Fix Edge TypeScript, dependency audit, FormatJS warnings, and console configuration.
  2. Run isolated BestChef CI from a clean clone.
  3. Build the approved SHA and distribute through TestFlight.
  4. Execute clean-install, upgrade, offline, recovery, abuse, localization, accessibility, performance, deletion, export, and moderation matrices.
  5. Complete App Store privacy, age, screenshots, review notes, support, deletion, and export answers against the binary.
  6. Close independent penetration and trust-and-safety reviews.
  7. Assemble immutable launch packet, rollback, ownership, and canary plan.
Exit: all commands green, current artifact passes, store package complete, external reviews closed, and every owner signs the same packet.
