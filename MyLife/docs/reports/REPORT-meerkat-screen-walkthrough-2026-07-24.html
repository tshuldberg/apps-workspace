Test these, in this order

  1. On both devices, open Settings → Connection server → "I have a server URL", paste the testbed's wss:// URL, and Save. Do this first; it avoids defect 2.
  2. Copy device A's pairing code into device B, and B's into A. Both should read "Paired devices: 1".
  3. Type the same phrase (16+ characters) on both.
  4. Press Listen on device B, then Sync now on device A within a minute or two.
  5. Expect completed · wan_relay · sent N / received M under Recent sessions.
  6. Check the message actually arrived on the other device.
  7. Turn on Automatic connections and confirm it dials paired devices while the tab is open.
Defect 2. If you rely on the built-in free default server rather than setting the URL yourself, the relay's health check expires after 60 seconds and is only refreshed when this dialog mounts. Sit here longer than a minute (which pairing always takes) and "Sync now" fails with "No relay URL configured" while the panel above still says "Free server reachable". Closing and reopening the dialog re-arms it.
Pairing being required on top of community membership is the biggest UX gap versus Discord or Slack. Worth a product decision before launch, independent of the two defects.

Test these

  1. Set your own server URL and save. This is also the workaround for defect 2.
  2. Point it at a URL that does not exist. The status must go unreachable and stay honest.
  3. Turn the free default off and confirm sync stops rather than quietly continuing.
  4. Press "Deploy my own" and read the self-hosting instructions.

Mobile app surface

The Expo app has 43 routes. None of them are testable on a phone right now: the native modules that make Meerkat different (Multipeer, Wi-Fi Direct, BLE wake, CallKit) are lazy-required and return null without an EAS dev build, and no build has been produced. To make the mobile app testable

  1. Run an EAS development build for iOS and Android.
  2. Install it on your own devices directly; for anyone else you need TestFlight, which needs App Store Connect set up.
  3. Deploy LiveKit before testing rooms.
  4. Until then, point every tester at the web app. On iPhone, Safari → Share → Add to Home Screen gives a full-screen app that behaves close to the native one for chat, communities, files, and DMs.
