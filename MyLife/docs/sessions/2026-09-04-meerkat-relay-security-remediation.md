## Changes

- Hosted relay admission: shared WebSocket backend waits for the relay's actual `ready` frame, rejects admission errors/early close/destroy/timeout, and retains frames received around admission. Previously an open socket was reported as successful before payment admission. Four regression tests fail against the old backend.
- Shared hosted-relay access: canonical exact configured endpoint matching, HTTPS/loopback-only billing endpoint, existing signed hosted authorization, bounded fetch deadline, single in-flight request, expiry-aware memory cache, failure cooldown and explicit reset. Self-host connections never receive a hosted token. No account-core/private-identity join was introduced.
- Mobile foreground/background sync, calls, rendezvous and public-join parking consume the existing relay backend through this shared access wrapper. Web public-join uses the same factory. Added mobile hosted-access status/retry card and optional paid relay build configuration, distinct from the free relay. Paid provider/billing proof remains unavailable; local fixtures are not live entitlement evidence.
- Invitations: closing a community preview retains the durable intent; successful join or explicit discard clears it. Mobile/web friend-code QR and copy actions follow an actual relay publication acknowledgement. The relay returns its actual capped expiry; legacy servers show unknown expiry, and expired codes require publication again. Acknowledgement matching includes the rendezvous ID. A one-use code may already have been redeemed, so remaining lifetime is not advertised as guaranteed availability.
- Security S1: Meerkat passes an explicit own-device predicate to NativeSyncEngine on web, mobile foreground and headless paths. Pairing and safety verification alone do not grant personal scope. Ownership requires the local own-device link, matching current pairing key, safety verification and, when present, a verified current person-group membership. Ordinary friend sessions receive shared scope only. Recipient filtering checks signed local community membership before serialization, preserves transport restrictions, drops unattributed rows/tombstones and unknown binary snapshots, and rechecks between batches. Personal rows/deletes require explicit ownership. Inbound application has the matching recipient gate. Blob requests must reference rows actually sent under that module and remain authorized after asynchronous loading and between blocks. Acknowledgement IDs come from each actual filtered batch.
- S1 compatibility: the generic sync API still allows integrations whose pairing contract already means personal ownership to omit the predicate. Every production Meerkat engine constructor supplies it. Untagged shared tombstones fail closed for friends; signed community delete events retain their community attribution. This is not a claim that every native transport has received physical-device validation.
- Security S3: the age-signal endpoint has no provider attestation verifier, so authenticated client assertions now return `503 not_configured`; invalid sessions remain unauthorized. Existing minor restrictions survive, and unattested legacy adult records are returned as unknown. Provider age verification remains unavailable. Previously persisted client passes and already issued credentials need separate migration/revocation assessment; no retroactive invalidation is claimed.
- Security S5: both preview cores fetch raster image bytes through the guarded fetch seam with credentials omitted, redirects rejected and a 2 MiB streaming limit. Decoders receive local data URIs only; native decoder rejects remote URLs itself. Mobile uses the installed Expo streaming fetch implementation. Text survives blocked targets, redirects, unsupported streams, oversized bodies and decoder failures. DNS resolution/rebinding protection and physical native validation remain open.
- Security S6: restored Gitleaks default detectors and added a checksum-pinned release verification job scoped to the four Meerkat source trees. Reviewed 20 source/fixture findings individually; exclusions bind exact match, exact file and detector. Found that directory scanning prefilters global allowlist paths, so conditional exclusions live at rule level. A fake GitHub token in an excluded fixture file is still detected. No real secret was found in the current source scan. Historical findings are not globally suppressed.
- S4 investigation: disabling Files sharing alone breaks the existing verified bulk-export destination. Retained configuration; migrate private SQLite, raw blobs, restore staging and rollback data together, while preserving explicit exports. Requires native storage/API and device evidence.
- Memory control: after the user's warning, checks run sequentially. Added `FUNCTION_GATE_MAX_WORKERS=1` to select one Vitest worker in the repository gate; the default remains two. No unrelated session processes were stopped.
