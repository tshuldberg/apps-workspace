Outcome

Dropbox, OneDrive, and Box implement the complete StorageDestinationAdapter contract over injected HTTP transport and access-token providers. The relay registry now loads all three from file-backed secrets and exact redirect allowlists. Mobile uses lazy PKCE plus SecureStore. Web uses short-lived broker sessions with no browser token persistence.

Only new provider-named files were added to the mobile storage-destinations directory. Shared files and the concurrent local-device packet were not touched.

Provider behavior

Dropbox

  • RPC and content endpoints under /2, upload-session resume, cursor listing, idempotent delete, and space usage.
  • Local 4 MiB-block content_hash with known-answer coverage, including a file larger than one block.
  • Each upload call hashes the bytes sent in that call. Returned metadata is compared against the whole ciphertext.
  • Path conflicts compare bytes and fail closed on mismatch.

OneDrive

  • Microsoft Graph special/approot addressing, ranged upload fragments, nextExpectedRanges resume, paging, and quota.
  • QuickXorHash is implemented from the published algorithm and covered by independent known-answer vectors.
  • QuickXorHash, SHA-1, or SHA-256 can prove provider checksum evidence. ETag and CTag cannot.
  • Preauthenticated upload URLs are origin-allowlisted and receive no Graph bearer token.
  • The selected short-lived Graph download URL is host-allowlisted and fetched without Authorization.

Box

  • An injected state seam caches the app-created folder id. There is no module-global state.
  • Chunk sessions carry per-part SHA-1 digests and whole-file commit digest validation.
  • Direct uploads send Box's required hexadecimal SHA-1 in Content-MD5 and then require read-back.
  • Commit evidence is accepted only when Box returns the same whole-file digest.
  • Box content locations are validated against the Box download boundary and fetched without bearer forwarding.
  • Marker paging, idempotent delete, quota, and fail-closed name-conflict handling are covered.

OAuth scope decisions

  • Dropbox: narrow file and metadata scopes. App-folder access must also be selected in the Dropbox console because it is an app setting.
  • OneDrive: Files.ReadWrite.AppFolder offline_access.
  • Box: Box has no app-folder scope. root_readwrite is the minimum usable content scope, so code enforces one dedicated app-created folder as the application boundary.
