# 2026-04-16: iOS dual-RN crash fix + hub tab bar polish

## Summary

Two fixes shipped in one session:

1. Resolved a simulator crash (`View config getter callback for component RCTActivityIndicatorView must be a function (received undefined)`) caused by two concurrent react-native versions bundling into the same Metro output.
2. Polished the floating hub tab bar so home-screen content no longer bleeds through behind it.

## 1. Dual react-native crash

### Symptom

On first launch of the iPhone 16e dev-client, every hub route rendered the module-error screen with:

```
View config getter callback for component `RCTActivityIndicatorView`
must be a function (received `undefined`).
```

plus 18x `Cannot read property 'default' of undefined` warnings.

### Root cause

Two independent issues, both cosmetic-looking but with real dependency effects:

1. `modules/books/package.json` dev-dependency `react-native: ^0.84.1`. Every other package in the workspace pinned `^0.81.5` (the version shipped with Expo SDK 54). pnpm satisfied both, so `modules/books/node_modules/react-native` symlinked to a separate 0.84.1 store path. Metro then bundled two react-native copies. The JS-side view-config registry that books (and any code routed through the books barrel) loaded was from 0.84.1, but the native `RCTActivityIndicatorView` pod came from 0.81.5 -- the internal shape had shifted, so the view-config getter came back `undefined`.

2. macOS iCloud Drive / Time Machine had left sync-conflict duplicates across node_modules: 43 in `apps/mobile/node_modules`, 12 in root `node_modules`, plus similar pollution under `packages/*`. Every duplicate carried a " 2" suffix (e.g. `react-native 2`, `@mylife 2`, `expo 2`) and pointed at stale March-era store paths including react-native 0.76.9. Although Metro will not directly import a module named `react-native 2`, Watchman indexed these trees, pnpm treated them as foreign files, and the resolver could not fully converge on a single RN graph.

### Fix

1. Changed `modules/books/package.json` devDependency `react-native: ^0.84.1` → `^0.81.5`.
2. Killed the running `expo run:ios` process, deleted every workspace `node_modules` directory (via `node -e "fs.rmSync(...)"` because the Bash sandbox blocked `rm -rf`), ran `watchman watch-del-all`, ran `pnpm install`, then restarted with `pnpm expo start --clear --dev-client`.

### Verification

- `readlink apps/mobile/node_modules/react-native` and `readlink modules/books/node_modules/react-native` both now resolve to the same `react-native@0.81.5_..._usigedqgzf7sk3gw4nhfuusx2y` store path.
- Zero " 2" suffix entries in `apps/mobile/node_modules` after reinstall.
- Metro booted cleanly on `localhost:8081` without a Watchman recrawl warning.

### Notes

- `pnpm expo start --ios` auto-routes to Expo Go, which cannot load dev-client native modules. Use `--dev-client` when the iOS app has already been built via `expo run:ios`.
- Native binary did NOT need to be rebuilt. It was already linked against 0.81.5 -- the mismatch lived entirely on the JS side.

## 2. Hub tab bar polish

### Symptom

Home-screen Library Modules scrolled visible icons directly behind the floating HOME/DISCOVER/SEARCH/SYNC/SETTINGS pill. The BlurView pill has `marginHorizontal: 12` so content was visible to the left and right of the pill, and the safe-area inset region below the pill had no background at all.

### Fix

Files touched: `apps/mobile/app/(hub)/{_layout,index,discover,search,data-sync,settings}.tsx`.

- `_layout.tsx`
  - New export: `HUB_TAB_BAR_CLEARANCE = 120`. Single source of truth for how much scroll padding each hub screen must reserve for the floating pill.
  - Added a `LinearGradient` as a full-fill sibling of the BlurView pill inside the wrapper. Gradient stops: `rgba(19,19,24,0)` → `rgba(19,19,24,0.85)` → `colors.background` at positions `0, 0.45, 1`. `pointerEvents="none"` so it does not intercept touches; wrapper itself switched to `pointerEvents="box-none"`.
  - Wrapper gained `paddingTop: 28` so the gradient has vertical room to fade out above the pill rather than starting abruptly at the pill edge.
- `index.tsx`, `discover.tsx`, `search.tsx`, `data-sync.tsx`, `settings.tsx`
  - Each replaced its scroll-content `paddingBottom` (`spacing.xxl` = 48, or the old literal `40` in index.tsx) with the shared `HUB_TAB_BAR_CLEARANCE` import, so content always stops cleanly above the gradient.

### Verification

- `pnpm typecheck` exits 0. (A transient stale hook reported `backToHub`/`backToHubLabel` errors in `(workouts)/(tabs)/_screen-kit.tsx`; those styles are actually present in the file at lines 346-362 and a fresh tsc run passes.)
- Metro re-bundled via Fast Refresh without errors.

## Patterns worth remembering

- When `pnpm-lock.yaml` gets regenerated, grep every `modules/*/package.json` and `packages/*/package.json` for `react-native` version pins. A single mismatched `^0.84.1` in a deep dep is enough to dual-bundle RN and produce the "view config getter undefined" crash, which looks like a native-module bug but is purely a JS duplication issue.
- iCloud-sync artifacts with " 2" suffix can accumulate silently in node_modules and poison pnpm resolution. The Watchman recrawl warning and stale old-SDK react-native versions in `node_modules/.pnpm` are tells. Full clean-install fixes it.
- A floating pill tab bar needs two things handled together: (a) the bar itself must cover its full footprint including margins and safe-area inset (solid or gradient), and (b) every scroll view below it must reserve that same footprint as bottom padding. Fixing only (a) leaves real controls sitting under the pill; fixing only (b) leaves transparent strips on the sides of the pill where content still bleeds through.
