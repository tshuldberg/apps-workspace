# MyNews trust and account contracts

Preserved from `MyLife/modules/mynews/CLAUDE.md` during the September 5, 2026 instruction reset. Paths in the retained text are relative to the originating project/package unless stated otherwise. Dated rollout notes are historical evidence, not current readiness claims. Consult the relevant contract when changing its implementation; generic agent workflow is governed by AGENTS.md.

## Invariants (do not break)

- Only the article's author changes the article's words; nothing merges without an author signature.
- Corrections and context suggestions require at least one https citation.
- Fee math conserves cents exactly; the platform take is `platformFeeBps` and nothing else.
- Honest empty states in shells; no demo content presented as live.


## Safety floor (Plan 39)

- Reporting (T6), block/mute (T7), moderation console + enforcement (T8), DMCA + repeat-infringer policy (T9), and the NCII / TAKE IT DOWN 48h SLA pipeline (T10) form the public UGC safety floor.
- **NCII / TAKE IT DOWN (T10):** `nw_ncii_cases` (append-only migration `20260705000009`, service-role-only) tracks a 48h removal SLA per ncii report. **Take-down-first:** an `ncii` report immediately retracts/rejects the content target (`nw_open_ncii_case`, called by `mynews-report` after insert) and opens a case; the 48h `deadline_at` is the window for HUMAN review of that removal, not a window the content may stay up. A profile/media target with no content row lands `queued` for the worker + human (fail-closed). The `mynews-ncii-worker` edge function (verify_jwt OFF in `config.toml`, gated by `X-MyNews-Worker-Secret` against `MYNEWS_NCII_WORKER_SECRET`, scheduled every 10m by `nw_run_ncii_worker` via pg_cron/pg_net) is the fail-closed backstop: it drives overdue unresolved cases to provable removal (`nw_ncii_enforce`, idempotent), escalates, and NEVER clears (only a human, in the console, clears with explicit confirmation; default is keep-removed). Hash-matching (StopNCII/PhotoDNA) and NCMEC CyberTipline are clearly-marked seams in `mynews-ncii-worker/seams.ts` with safe defaults (unconfigured -> pending/human review, never a fabricated match or ref); founder-ops wires the vendor + creds + worker secret + cron config rows (`nw_job_config`). Console queue: `apps/mynews-console/app/ncii/`.
- **DMCA (T9):** `nw_dmca_notices` (append-only migration `20260705000008`) captures the 17 U.S.C. 512(c)(3) elements (name, contact, work, infringing URL, good-faith + accuracy attestations, signature). Intake via the `mynews-dmca` edge function (gateway JWT verification stays ON: the web BFF sends the anon key and signed platform-IP headers, the app sends the user session; validated + token-bucket rate-limited per account or per signed platform IP + submitter email, fail closed); a takedown notice spawns a linked `copyright` report so it lands in the moderation queue. Teeth: `nw_moderate_strike_and_maybe_suspend` increments `nw_profiles.copyright_strikes`, audits, and suspends at 3 strikes (service-role only). Published takedown/contact/SLA info on web `/legal` + `/legal/dmca` and in-app `(root)/legal.tsx`. Pure validation twin: `src/data/dmca.ts` (exposed on the `cloud-fetch` subpath). Copy states the process and where notices go; it does NOT claim a registered designated agent (founder-ops registration step).


## Account lifecycle (Plan 48 WP5)

- **Deletion is a job, never an in-request wipe.** `nw_deletion_requests` (migration `20260730000006`) holds one in-flight request per user across `grace -> processing -> completed | cancelled | failed`. `nw_account_deletion_initiate` opens a 7-day grace row (cancellable for the whole window via `nw_account_deletion_cancel`, grace only); `nw_account_deletion_claim_due` promotes due rows plus stalled/failed rows past a one-hour backoff; `nw_account_deletion_dispose` performs the entire content disposition in ONE transaction. The 7 days live in the SQL and are mirrored by `ACCOUNT_DELETION_GRACE_DAYS` in `src/data/account.ts`, pinned by a drift test.
- **auth.users cascade fix (load-bearing).** `nw_profiles.user_id` is now nullable with `on delete set null`. Disposition DETACHES the retained profile before the worker deletes the auth user; otherwise deleting the user would either fail on `nw_articles.author_id`'s `on delete restrict` or cascade the whole retained public record away. A detached profile fails every `auth.uid() = user_id` policy closed.
- **Disposition policy.** RETAINED + ANONYMIZED: published/retracted articles, revisions, accepted/partial suggestions, endorsements and the credibility ledger stay; identity becomes `deleted_<random>` / "Deleted account" with the Ed25519 key cleared and `pubkey_revoked_at` set, so no NEW revision can verify. RETAINED for legal/safety/tax: reports, DMCA notices and counter-notices, NCII cases, moderation actions, charges, receipts, transfers (recurring support is cancelled and the payout identifier is cleared). HARD DELETED: follows, blocks, newsroom memberships, verification evidence, terms acceptances, thread comments, open/rejected/stale suggestions, and drafts (a collaborative draft that already awarded another editor credibility keeps its row with the author's words and signatures scrubbed).
- **User-facing function** `mynews-account` (gateway JWT ON, NOT listed in `config.toml`): `initiate_deletion` requires the typed phrase `DELETE MY ACCOUNT` exactly AND an access token issued within 10 minutes (a fresh-session signal, not proof of re-typed credentials, which is why the typed phrase and the cancellable window both exist); plus `cancel_deletion`, `deletion_status`, and a synchronous `export_data` bounded at 8 MiB. Suspended accounts keep both paths: deletion and export are rights.
- **Worker** `mynews-account-worker` (verify_jwt OFF, `X-MyNews-Worker-Secret` against `MYNEWS_ACCOUNT_WORKER_SECRET`, hourly via `nw_run_account_worker` + pg_cron): dispose, admin-API auth-user deletion, processor-cleanup seam (`seams.ts`, unconfigured -> `skipped-unconfigured`, configured -> real https POST), then complete. Unconfigured admin credentials or processor rail record `skipped-unconfigured`, which stays VISIBLE in the status and is never rewritten as `done`; failures land `failed` + `failure_detail` and are retried.
- **Export** is `nw_account_export_bundle`: one jsonb snapshot of every user-owned row, always with all sections present (empty array over missing key). `nw_export_jobs` is the audit of the request and never stores the data. The section list is pinned to the in-memory store twin by a drift test.
- Disclosure copy lives once, in `src/data/account.ts` (`ACCOUNT_DELETION_RETAINED` / `ACCOUNT_DELETION_REMOVED`), and is rendered by the privacy policy, the in-app screens (`apps/mynews/app/(root)/account-delete.tsx`, `account-export.tsx`), and the public `/account/delete` page. That page ships NO form: the site has no sign-in yet, so it states where deletion actually happens instead of pretending to verify a visitor.


## Journalist support hardening (Plan 48 WP7)

- **Velocity limits are durable, not in-memory.** `nw_support_rate_counters` + `nw_consume_support_rate_limit` (migration `20260730000007`) hold two token buckets per checkout attempt: the SUPPORTER (capacity 10, one token per 360s = 10/hour) and the JOURNALIST RECIPIENT (capacity 60, one per 60s = 60/hour). Same shape as `nw_consume_dmca_rate_limit`, including bounded opportunistic GC. The edge fails CLOSED (503) if the counter call errors and returns 429 on a refusal, always before the provider call.
- **Idempotency is real.** `nw_support_checkout_attempts` records one row per CONFIRMED attempt keyed by the client's stable key. `nw_begin_support_checkout` is the single atomic entry point: it replays the original checkout URL for a repeated key, returns `conflict` for a key reused with a different journalist or amount, charges both buckets only for a genuinely NEW attempt, and never inserts an attempt the buckets would have refused. `nw_record_support_checkout_url` records the provider URL (first write wins) so the next retry replays instead of opening a second session. The client's stable key comes from `nextSupportConfirmation` in `apps/mynews`.
- **Payout attribution works against real Stripe Connect.** Automatic payouts on Express accounts carry EMPTY metadata, so the old metadata-only branch rejected every real payout as `invalid-payout-metadata` and `paidOutCents` could never leave 0. `mynews-payments-webhook` now reads the event ENVELOPE's top-level `account` field (`connectAccountRef`, `acct_` shape validated), resolves the journalist through `nw_payout_accounts.provider_account_ref`, and passes both to `nw_apply_payment_event` (now 7 args, the two new ones defaulted for rollout safety). The RPC resolves authoritatively from the stored account ref, rejects a caller-supplied id that contradicts it or the object metadata as `payout-attribution-conflict`, and records an unresolvable payout as a typed `unattributed-payout` failure on `nw_payment_events` (return value `unattributed`) with NO ledger row. `account.updated` now also resolves by account ref when journalist metadata is absent.
- **Reconciliation actually runs.** `mynews-support-worker` (verify_jwt OFF, `X-MyNews-Worker-Secret` against `MYNEWS_SUPPORT_WORKER_SECRET`) loads the ledger, runs the reconciliation invariants, and writes an `nw_support_reconciliation_runs` row (ok/mismatch counts plus findings bounded to 100 entries; the true total stays in `mismatch_count`). It only reports: the ledger is append-only by trigger, so a mismatch is an engineering signal. A ledger-read failure records NOTHING and reports not-ok; a run-row write failure also makes the pass not-ok, because a passing row it could not write would be a lie. Console view: `apps/mynews-console/app/support/`.
- **Twin parity:** the worker cannot import the TS package, so the reconciliation logic is mirrored in `supabase/functions/_shared/mynews-support-reconcile.ts` and pinned to `src/data/support.ts` by `mynews-support-worker/__tests__/reconcile-parity.test.ts` (case table + 200 seeded random ledgers). Change both sides together.
- **Capability-keyed legal copy on web:** `createLegalContent` and `detectMyNewsCapabilities` are re-exported on the `cloud-fetch` subpath so `apps/mynews-web` can build the bundle per request instead of shipping the frozen unconfigured export set.


## Screening, taxonomy, verification (Plan 48 WP8)

- **The screening engine is pure and generated into the edge.** `src/screening/` is normalize -> per-class lexicon passes -> URL reputation -> structure anomalies -> per-class thresholds, with no clock, no randomness, and no I/O. The edge cannot import the package, so `supabase/functions/_shared/mynews-screening.ts` is GENERATED from these files by `scripts/gen-mynews-screening-twin.mjs` and byte-checked by `screening/__tests__/edge-twin.test.ts`. Never hand-edit the twin; run the generator.
- **Per-class thresholds, not one score.** `CLASS_POLICY` in `screening/types.ts` is the source of truth. `child-safety` (0.25) and `self-harm` (0.4) are `humanOnly`: no automated path clears them, and a vendor cannot lower them. Class scores saturate at 1 and there is no global score that can quarantine on its own.
- **False-positive control is part of the engine, not an afterthought.** A term inside a quotation or after a reporting attribution scores at half weight (`QUOTED_CONTEXT_MULTIPLIER`), and two or more warning markers halve fraud and spam (`ADVISORY_MITIGATION`). This is what lets a news product publish coverage of abuse and scam warnings. The clean half of `screening/__fixtures__/corpus.ts` is the contract; changing it is a product decision.
- **Evasion is aggravating.** Four normalization views (normalized, folded, de-separated, squeezed) with the last two gated on independent evasion evidence. A match that only survives de-obfuscation scores higher, not lower.
- **Held content is never public, and the representation is deliberate.** A held article stays `status = 'draft'` (every existing public read path already excludes drafts, so no new status value could silently satisfy a dozen predicates); a held revision does not advance `nw_articles.current_rev`; a held suggestion carries `status = 'quarantined'`; a held comment carries `screening_status`. Migration `20260730000009` tightens exactly three public policies to match.
- **Review-accept HOLDS instead of quarantining.** Review's invariant is that the server never composes article text, and awards ride live aggregates, so a flagged accept writes no content at all: the decision row carries the refused envelope and an approval issues a content allowance (`nw_screening_allowances`, keyed on author + sha256) so the author's identical resubmission goes through. Without the allowance the approval loop would never terminate.
- **Fail closed.** Any screening read or write failure is a retryable 503 at the edge and writes nothing. `_shared/mynews-screening-gate.ts` is the single implementation all four write edges call; a vendor is optional, may only ESCALATE, and an absent vendor is an explicit `unconfigured` state, never a verdict.
- **Taxonomy lives in `src/taxonomy.ts`, not `data/`,** so the console and Server Components can import it through `@mylife/mynews/engines` without pulling the cloud port. Four copies of the SLA table (module, edge store, SQL seed, console) are pinned against each other by `check:mynews-parity` plus tests on all three TS sides.
- **The urgent case lane is shared, not forked.** `nw_ncii_cases` gained `case_class`; `nw_reconcile_urgent_case` reads the lane and the deadline from `nw_report_sla` (child-safety 24h, NCII 48h) and `nw_reconcile_ncii_case` delegates to it with its original return vocabulary.
- **A verified badge always has a record behind it.** `nw_verification_decide` / `nw_verification_revoke` / `nw_verification_expire_due` move `nw_journalists.tier` in the same transaction as the verification row, and the app and web badges render off `verificationState`, not the tier column.
- **Sybil gates fail inert, then hard.** `levelFor` withholds elevated trust for a young account or a ring-flagged profile, but ONLY when the signal is present: a caller with no age signal cannot silently re-gate every editor. `engines/rings.ts` is a pure detector whose output the console persists to `nw_ring_flags`; it never enforces on its own.


## Observability and health (Plan 48 WP11)

- **One structured JSON line per request, from every `mynews-*` function.** `_shared/mynews-observability.ts` is the single implementation; `serveEnvelope` now takes a required `{ fn, action }`, so a new function cannot ship without a name in its logs. Fields are a CLOSED set: `level, service, fn, action, outcome, status, durationMs, requestId, method, timestamp, subjectHash, extra`. Nothing is ever spread in from a request, header, body, or row.
- **No PII, enforced by a canary test rather than by review.** `extra` accepts numbers and booleans only (a string is dropped, which is how a headline or an email would otherwise arrive); actions must match `^[a-z0-9][a-z0-9_-]{0,47}$`, so a caller-supplied body value that failed validation cannot reach a log line; identity appears only as `subjectHash`, a truncated SHA-256 of the JWT sub. The request PATH is not logged either, because MyNews function URLs carry handles and slugs.
- **Outcome tagging changes no bytes.** `jsonOk`/`jsonError` stamp the typed envelope code onto the `Response` via a non-enumerable Symbol property, so the serialized body, status, and headers are byte-identical to an untagged response. Never replace this with a header or a body field.
- **The line is emitted awaited, not fire-and-forget.** A task started after the response races the edge isolate's teardown, and a log line that might be written is not observability.
- **`mynews-health`** (verify_jwt OFF): the SHALLOW payload `{status, checkedAt, detailAvailable}` is public so an uptime probe and `scripts/mynews-smoke.sh` work with no credential, and it deliberately names no queue, depth, or age (an attacker watching the NCII queue drain learns when moderation is thin). The DETAILED payload needs `MYNEWS_HEALTH_SECRET`; a wrong secret is a 401 and NEVER a silent downgrade to shallow, and an UNSET secret makes detail unavailable (503) rather than open. A failed snapshot read is 503 with status `down`, never `ok` because zero rows came back.
- **Health classification is a twin, like screening and bounds.** `src/data/health.ts` is canonical (exported on the `@mylife/mynews/health` subpath); `_shared/mynews-health.ts` is the edge mirror. `_shared/__tests__/mynews-health.test.ts` runs BOTH over the same fixture matrix and asserts identical output. Change one, change both. Import the subpath, not the barrel, from a Server Component: the barrel reaches the signing module and `@mylife/sync`, which fails `next build`.
- **Fail-closed classification.** A missing or disabled threshold row is `unknown`, never `ok`. A worker that has never written to `nw_worker_runs` is `unknown` with a null age, never a fabricated heartbeat. A recent but FAILING worker pass is at least `warn`. An NCII case past its deadline is `alarm` regardless of age thresholds, because that deadline has a legal shape.
- **Migration `20260730000012`** adds `nw_worker_runs` (uniform heartbeat, written by all three workers via an optional `recordRun` dep wired only at the `Deno.serve` bootstrap, so no unit test performs a network write), `nw_health_thresholds` (alarm config as DATA, so retuning during a spike needs no deploy), `nw_health_snapshot()` (service-role only), and `nw_run_support_worker()` (the support reconciliation worker previously had no cron caller at all, unlike its two siblings).
- Console surface: `apps/mynews-console/app/health/`. Env matrix: `apps/mynews/docs/ENV_MATRIX.md`, generated by `scripts/gen-mynews-env-matrix.mjs` and gated by `pnpm check:mynews-env-matrix`. Runbooks: `apps/mynews/docs/runbooks/`.
