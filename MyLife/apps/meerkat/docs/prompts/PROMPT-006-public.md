## 3. Lessons learned

- **EXPO_PUBLIC inlining contract:** an `EXPO_PUBLIC_*` value exists in a release bundle only where the source contains the literal member expression `process.env.EXPO_PUBLIC_NAME`. Captured objects, destructuring, and dynamic keys silently return undefined in TestFlight/production while working in dev, Expo Go, and Vitest. Web (Vite) has the same rule with `import.meta.env.VITE_*`.
- **Navigation, Alerts, and RN modals do not mix in one commit.** Never unmount a visible RN `<Modal>`, navigate, present a second Modal, or fire `Alert.alert` while one is dismissing. Fix shape: queue the action in a ref, flush from Modal `onDismiss` (iOS) plus a Platform-gated visibility effect (Android unmounts children the instant visible flips). The queue lives in a component that SURVIVES dismissal. The hazard hides behind SEAMS: a provider method that navigates before its first await (startCall), and now a shared sheet whose `onVerified` host callback ends in an Alert two calls deep (VerifySheet join). When a shared sheet's callbacks may alert/navigate, either put the queue inside the sheet or have the sheet expose an `onDismissed` hook and queue in the host. Keep last content rendered during dismissal (`displaySelected` shape).
- **try/finally without catch is the recurring "tap does nothing" bug; an await OUTSIDE the try is the same bug.** Every async handler needs a catch rendering an honest failure; awaits and throwing sync calls (hex parsers, key extraction, signing) belong INSIDE the try and the busy window; a `void promise` without `.catch` is the same bug in a different jacket. BUT verify at the seam first: this repo's client cores overwhelmingly fold network + json into result unions and genuinely cannot reject (probe/load/submit/export/acquire families), and adding catches there is noise. The genuinely-throwing seams found so far: `ensureEffectiveRelayUrl` (and anything awaiting it, e.g. `requestPublicJoin`, `createDmGroup`), secure-store/keychain writes (`generatePublicPersona`, `setStoredPersona`), bare `signMessage`/`extractSigningPrivateKeyHex` (`persistPublicReport`), Clipboard, filesystem/blob stores, and engine cores. DB k/v get/set is the trusted bare idiom.
- **A dropped result union is the same dead tap as a swallowed rejection.** Render every union; single-source repeated failure copy in a CORE_TWIN helper with a surface parameter rather than duplicating inline maps.
- **Any async result applied to state needs a supersede guard when the input can change underneath it.** The discover probes had `probeSeq` from day one; the publish sheet's host probe did not, and the stale result was SECURITY-ADJACENT (a stale "reachable" gates Publish, breaking the fail-closed promise in the comment right above it). Rule: every `setX({done, result})` after an await gets `if (seq.current !== seq) return;`, and every edit of the underlying input bumps the seq. The same class in timer form: an auto-close/auto-back `setTimeout` must be owned (cleared on unmount) and must verify its target is still current (close only ITS report sheet, functional-set compare).
- **A real write needs confirm or feedback, and success copy is claimed only after the await resolves.** Silent hammerable writes (call report), unconfirmed destructive one-taps (block author), and fake-success copy are all the same honesty bug. Single-use resources (humanity tokens) additionally need a synchronous single-flight ref so two fast taps cannot spend twice; on a thrown submit, do NOT clear the resource, and say so honestly.
- **Back affordances need `router.canGoBack()` with a fallback on EVERY deep-linkable screen** (nearest sensible parent; derive from route params on dual-entry screens). NEW variant: a screen reached via `router.replace` may have NO back affordance at all (persona settings); check every screen has one, not just that existing ones fall back.
- **Domain rules must be swept PER SURFACE and PER ENTRY POINT; "read-only" means every write verb including external intake** (pickers, share intake, forwarding, deep links). Filter at the offer stage, keep a stale-selection repair, and RE-DERIVE every enable/disable predicate from the filtered truth.
- **Error surfaces must live in the pane the user is looking at.** A catch that reports into a sibling only rendered for another mode (managed-tier error block for a self-host copy failure) is a hidden-pane failure; give the failing control its own adjacent surface.
- Controls toggle off observed state, never hardcode the "on" direction; fail-closed rendering: an error state must not resurrect affordances the failure disproved; selection/pick state self-repairs when its referent disappears, including per-open reset of sheet-local state.
- Cross-surface drift hides in half-applied hardening: diff the twin the moment you find a bug once; a whole feature or a whole guard (probeSeq) missing on one surface is the same drift one level up.
- Multi-step sequential mutations over a device list need single-flight + a partial-failure notice.
- A parity-locked string changes by updating surfaces AND the lock needle in `scripts/check-meerkat-parity.mjs` in the same change; ADDING strings is free; byte-identical core twins (public-publish.ts) and anchored twins (public-directory-client, public-reader-core, discover-core) must be edited on both sides or not at all. Em dashes are banned even in UI copy.
- Guard tests that scan source are the accepted way to pin screen wiring: scope regexes, count occurrences, pin structural absences (`not.toContain('void Clipboard.setStringAsync(view.link)')`), and make each lock fail on revert for the right reason.
- Repo idiom: screen logic goes in a pure `data/*-core.ts` with unit tests; every new mobile core needs a `CORE_TWINS` entry or exception in the parity script in the same change.
- Billing/entitlement truth: mobile `data/app-unlock.ts` + gate in `(root)/_layout.tsx`; web `lib/hosted-access.ts` + `AppUnlockSection.tsx`. Price never hardcoded ($4.99 one-time + $4.99/mo hosted, founder-locked). A "connection server" is the wss relay; the hosted billing service is `MEERKAT_HOSTED_API_URL`; never conflate them in copy.
- Live-testing the web app locally: Vite on :5199 with `VITE_MEERKAT_HOSTED_API_URL` at a scratchpad stub answering `GET /api/entitlements/meerkat-app` `{"unlocked": true}` (CORS `*`), then the real "Restore purchase" in Settings. Age gate + onboarding + restore in ONE uninterrupted session; keep default names; never click window.confirm/alert paths in automation (source-lock them). Close stale app tabs before wiping site data, and AWAIT every `indexedDB.deleteDatabase` (onsuccess/onerror/onblocked) before reloading: a fire-and-forget wipe racing a live instance reproduces the browser-secret-store corruption AND the "Meerkat could not start" terminal state, while an awaited wipe boots clean. Staging a share for picker tests works headlessly by setting the hidden file input's files via DataTransfer + dispatching `change`. The iOS Simulator has no tap driver; mobile interaction checks are founder device checks.
- A background persist loop that retries immediately on failure turns a permanent failure into a silent hot loop with memory-only data; failures need backoff, a cap, and an honest surface; create-if-absent of a shared crypto key must run under the same lock as the writes it protects.
- A catch that maps every failure to a default state can hide a broken precondition; distinguish precondition failures from a genuine negative result. Change-notification seams that skip byte-identical writes fire NO listeners on a re-validate producing the same value.
- `HonestNotice` (mobile kit.tsx) takes `tone: 'info' | 'warning' | 'danger'`; blockers must not use the default green. `markOnboardingComplete` fires listeners synchronously inside the caller's handler.
