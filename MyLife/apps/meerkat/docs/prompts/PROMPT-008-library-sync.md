## 2. Resolution report

### Fixes (all in the working tree, uncommitted, alongside Sets 0-6)

- **Back fallbacks (issue 1):** every deep-linkable library screen + Sync Close now use `if (router.canGoBack()) router.back(); else router.replace(<sensible parent>)`. Parents: My Library hub -> `/me`; a single library -> `/library`; item detail -> `/library/${item.channelId}` (its channel), `/library` in the item-missing branch; player + reader -> `/library/item/${itemId}` (fallback `/library` when itemId is absent); Sync Close -> `/me`. Web screens navigate via `dispatch` (no `router`), so no change needed there.
- **Release catch (issue 2):** mobile wraps the release+refetch in try/catch -> `Alert.alert('Could not remove this copy', ...)`; web adds the rejection arm to `lib.releaseItem(item).then(ok, err => window.alert(...))`, matching the keep path.
- **Open/Download catches (issue 3):** mobile `openContent` gains a `catch` before the `finally` -> `Alert.alert('Could not open this item', ...)`, and the inner document share-out async gets `.catch(err => Alert.alert('Could not open the file', ...))`; the player's open-with-another-app gets the same inner `.catch`. Web `doDownload`/`doOpenPdf` wrap the whole body in try/catch -> `setOpenError('This file could not be opened.')`.
- **Remove catch (issue 4):** mobile wraps `tombstoneLibraryItem` in try/catch (`Alert.alert('Could not remove this item', ...)`; `return` on failure so navigation never fires), then navigates with the canGoBack fallback ONLY on success; web adds the rejection arm -> `setOpenError('This item could not be removed.')`, keeping `backToLibrary()` on success only.
- **Web reader/player stranded-spinner (issue 5):** `LibraryPlayer` wraps the load body in try/catch -> `setState('error')`; `CbzReader` and `EpubReader` move `const bytes = await lib.openContent(item)` INSIDE the existing try so a decrypt throw lands in the `catch` -> `setState('error')` instead of stranding `'loading'`. ## 3. Lessons learned

- **Create-if-absent of a shared crypto key must run under the SAME lock as every write it protects, and the key's identity must be stored so a mismatch is detectable.** A read-then-create without a lock mints two keys under any concurrency (StrictMode, a second tab, a wipe race); stamping records with the id of the key that wrote them turns an undecipherable OperationError into a deterministic, typed, recoverable half-state. Pair it with a single-flight PROMISE cache on the boot path: caching only the resolved value still runs N concurrent boots.
- **A background persist loop that retries immediately on failure is a hot loop; and clearing write-authority state BEFORE the write commits silently loses data on failure.** Failures need exponential backoff, a surface threshold, and an honest banner; authority sets get snapshotted per round and restored on failure; a provably-permanent failure (re-keyed store) is FATAL: surface once, never retry, never overwrite the other session's data. `flush()` must REJECT on a failed attempt. A read-merge-adopt cycle over a shared record must never adopt the stored base over a key with a PENDING local write.
- **Boot half-states deserve a RECOVERY SCREEN, not an error line.** Detect them typed (undecryptable vault, identity row without its signing key), render what is lost, what is not, and the real options (restore-from-backup, confirmed start-fresh with an AWAITED wipe). A messageless fallback for non-Error throws is a bug: always derive `message || name || String(error)`.
- **One validated state machine, one consumer surface.** Distinguish checking / verified-yes / verified-no / CANNOT-VERIFY (fail-closed but honest, with retry); put the machine in the provider; have every surface read it. Change-notification seams must fire on every authoritative answer, including byte-identical ones; make re-validation loop-free by ADOPTING in-session answers instead of re-fetching on notify.
- **A destructive flow may navigate away ONLY on real success.** `finally { navigate }` after a revoke/disconnect/delete/tombstone shows the failure alert mid-navigation and leaves the world looking like the action happened. Track success and gate the navigation; failure copy must say "Nothing was …"-style truth. (Set 7: the tombstone `router.back()` fired unconditionally after the await, with no catch — the same class, one layer up.)
- **Every mutating storage/backup/restore/connect/ingest flow needs a synchronous single-flight ref; state-based busy flags have a re-render gap.** And every selection over a FILTERED list needs stale-selection repair: re-derive the effective target, never `selected ?? first`.
- **Clipboard, share-sheet, SAF/file picker, secure store, signing, sealed-decrypt, blob store, and account flows are genuinely-throwing seams; claim success only after the await resolves.** "Copied"/"Saved" set before/without the promise resolving is fake success; a missing API (`!navigator.clipboard`) must SAY so, not no-op or claim success (Set 7 web SyncDialog claimed "copied" whenever clipboard was absent). But verify at the seam first: this repo's client cores fold network+json to result unions — no catch noise there. `try/finally`-without-catch is the recurring "tap does nothing" bug (Set 7: mobile item `openContent`); busy/loading resets belong in `finally`, the ERROR handler belongs in a `catch`.
- **openContent / sealed-decrypt is a throwing seam and its await must sit INSIDE the try that owns the load state, or a throw strands the spinner.** A `void (async () => { const bytes = await open(); ... try {parse} catch {} })()` leaves the open() throw uncaught and the state at `'loading'` forever. The fix is trivial (move the await inside the try) but it is a per-surface drift magnet: the mobile reader had it right and all three web readers/players had it wrong. Diff the twin on every find.
- **A dropped result union is a dead tap** (`if (id) navigate;` with no else); render every branch. A wizard phase entered before its data exists must have an escape: on a setup throw, fall BACK to the phase whose panel renders the error and the retry.
- **Navigation, Alerts, and RN modals do not mix in one commit.** Never unmount a visible `<Modal>`, navigate, present a second Modal, or fire `Alert.alert` while one is dismissing. Queue the action in a ref and flush from Modal `onDismiss` (iOS) + a Platform-gated visibility effect (Android). In-sheet two-step confirms (Delete > "Delete forever" / "Keep it") avoid stacking an Alert on a Modal entirely. (A plain `push`/`dispatch` after `setVisible(false)` — no Alert, no second Modal — is lower risk and was left as is in the create-library sheets; see Set-7 follow-up.) The subtle variant: a catch that fires `Alert.alert` and then falls through to `setVisible(false)` closes the sheet UNDER the alert in the same commit: on iOS the dismissal tears the alert down and the failure is swallowed. The fix doubles as honesty: `return` from the catch so the sheet closes only on real success and the user keeps their input for a retry (Set-7 review pass, all four item-detail sheet handlers).
- **Back affordances need `router.canGoBack()` with a fallback on EVERY deep-linkable screen, including screens reached only via `push` from one entry point (library subtree), shared headers, and deep-link TARGETS.** One bare `router.back()` per screen is one dead cold-link. Pick the sensible parent per screen (item -> its channel, player/reader -> the item, a library -> the hub, the hub -> its entry tab).
- **Any async result applied to state needs a supersede guard when the input can change** (seq refs on probes/validators; the `cancelled` flag on load effects); auto-close/auto-back timers must be owned and verify their target is still current.
- **Error surfaces must live in the pane the user is looking at**; a state set but never rendered is the same bug one step later; treat an unused-var lint warning as a correctness signal.
- Domain rules must be swept PER SURFACE and PER ENTRY POINT ("read-only" means every write verb incl. pickers/intake/deep links); re-derive enable predicates from filtered truth; controls toggle off observed state; fail-closed rendering never resurrects affordances the failure disproved.
- **Cross-surface drift hides in half-applied hardening: diff the twin on EVERY find, including the finds you fix.** Set 7 alone: the release-copy catch, the openContent-stranded-spinner guard, the tombstone catch, and the pairing-clipboard honesty all existed as bugs on BOTH surfaces (or as a mobile-right/web-wrong drift); and the issue-8 edit-catch FIX itself landed mobile-only, leaving the web twin's edit/tag/collection signing writes bare until the review pass. A "web wrappers fold to result unions" assumption must be checked per method: `editItemMetadata` signs and executes SQL synchronously and genuinely throws.
- **Transport / availability honesty (Plan 38 + Sync):** every number on the Sync screen and every "Held on this device" / stats value comes from the engine, the `sync_` tables, or a real store query — never a fabricated peer/transfer/backup/seeder count. Availability copy for community library blobs must never imply always-on ("Available from members who have it, when a sync connects."). The parity script locks the honest state strings; adding new failure copy is free, editing a locked string needs the needle updated in the same change.
- Plan 51 wall holds: account flows never touch the mesh identity; `cannot_verify` never renders as not-entitled.
- **EXPO_PUBLIC / VITE env inlining contract:** values exist in release bundles only as literal member expressions (`process.env.EXPO_PUBLIC_X`, `import.meta.env.VITE_X`); captured objects and dynamic keys silently return undefined in production while working in dev and tests.
- **Programmatic form fills are not user input.** Verify input-driven bug reports with REAL typing before changing product code (the age-gate "two clicks" report was a scripted-fill artifact; re-confirmed first-click-passes live in Set 7).
- Guard tests that scan source are the accepted way to pin screen wiring; make each lock fail on revert FOR THE RIGHT REASON (anchor a regex to the specific construct, not a string that appears elsewhere — the LibraryPlayer catch shares `setState('error')` with the MSE catch, so the assertion had to anchor on `pendingBytesRef.current = bytes; setState('ready'); } catch`). A parity-locked string changes by updating BOTH surfaces AND the needle in `scripts/check-meerkat-parity.mjs` in the same change; adding strings is free. Em dashes are banned even in UI copy. Screen logic goes in a pure `data/*-core.ts` with unit tests; every new mobile core needs a `CORE_TWINS` entry or exception.
- Billing/entitlement truth: web `lib/hosted-access.ts` + the provider's `appUnlock` machine + `AppUnlockSection`; mobile `data/app-unlock.ts` + the `(root)/_layout.tsx` gate. Price never hardcoded ($4.99 one-time + $4.99/mo hosted, founder-locked). A "connection server" is the wss relay; the hosted billing service is `MEERKAT_HOSTED_API_URL`; never conflate them in copy.
