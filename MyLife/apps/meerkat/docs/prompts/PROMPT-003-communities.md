## 3. Lessons learned

- **EXPO_PUBLIC inlining contract:** an `EXPO_PUBLIC_*` value exists in a release bundle only where the source contains the literal member expression `process.env.EXPO_PUBLIC_NAME`. Captured objects, destructuring, and dynamic keys silently return undefined in TestFlight/production while working in dev, Expo Go, and Vitest. Check this first for any "works locally, unconfigured in TestFlight" symptom. Web (Vite) has the same rule with `import.meta.env.VITE_*`.
- **Navigation and RN modals do not mix in one commit.** Never unmount a visible RN `<Modal>` (toggle `visible` instead; if per-open fresh state matters, remount via a per-open counter key so the remount happens while hidden), never navigate imperatively or present a second Modal while one is dismissing, and never guard a route by returning `<Redirect>` in place of a layout's own `<Stack>`. The accepted fix shape: queue the action in state, flush it from Modal `onDismiss` (iOS) plus a Platform-gated visibility effect (Android). Sweep pattern: grep every `<Modal` screen for `setXOpen(false)`/`setItem(null)` adjacent to `router.` or another `setYOpen(true)`/`setScanning(true)`, and for `{show ? <SomeSheet visible` conditional mounts. When the navigation decision is computed inside the modal body, lift the queue into the Modal-owning wrapper and pass an `onNavigate` callback down (InvitePreviewSheet shape).
- **A dismissal-flushed queue must live in a component that SURVIVES the dismissal.** RN 0.81 Modal facts (verified in source): `onDismiss` fires on iOS ONLY; on iOS a Modal keeps rendering its children until the native dismissal completes (`isRendered`), but on Android children unmount the instant `visible` flips false. So a queue held inside a sheet that is itself a CHILD of another Modal dies with that Modal's hide-commit (Android loses the action; iOS can flush mid-parent-teardown, the freeze class). When a host wraps the queueing sheet in its own Modal, the HOST must own the queue (InvitePreviewSheet's optional `onNavigate` override + OnboardingGate is the shipped shape). Sweep pattern: for every dismissal-flushed queue, find every host and check whether the queue's component can unmount before the flush.
- **try/finally without catch is the recurring "tap does nothing" bug.** `finally` resets busy so the UI looks idle while the rejection vanished. Every async handler needs a catch that renders an honest failure; prefer a pure `data/*` flow returning a result union. Sweep the WHOLE file including mount/boot effects and fire-and-forget `void promise` calls (banner loads, `Share.share`, clipboard writes) - a `void` without `.catch` is the same bug wearing a different jacket. A catch that returns early without rendering anything just converts the rejection into a quieter dead tap.
- Success copy ("Copied", "Sent", "Saved", "Layout template copied") is claimed only AFTER the await that makes it true resolves; a try/catch around a `void asyncCall()` protects nothing. Web `navigator.clipboard.writeText` genuinely rejects (focus/permission), so this is not theoretical.
- Back affordances need `router.canGoBack()` with a fallback route on EVERY deep-linkable screen (Expo Router makes almost every route deep-linkable): entitlement-gate replaces, OS-share/invite deep links, and relaunch restores all create only-route states. Fall back to the nearest sensible parent (community home for community subscreens, the pages directory for a page), not always the tab root; a locked-state fallback must target a FREE route.
- Fail-closed rendering: an error state must not resurrect affordances the failure just proved impossible; a picker must not offer destinations that can only fail; key any "you need X first" notice on what is actually offered.
- Selection/target state must self-repair when its referent disappears; "default only when null" effects leave stale targets.
- When one row (or one list of rows) has several action buttons sharing a flow, busy state needs a per-action or per-item dimension (`{id, action}` / `busyCanvasId`), or every button claims the in-flight verb.
- Cross-surface drift hides in half-applied hardening: when one surface's comment claims it "matches" the twin (web toggleBlockPerson), DIFF the twin - the mobile side had neither the single-flight nor the error signal, and CreateCommunityDialog's from-scratch path lacked the catch its own template path had. Also check both surfaces for the same bug class the moment you find it once (clipboard claims, per-row busy existed identically on both).
- Multi-step sequential mutations over a device list need single-flight + a partial-failure notice ("Only N of M devices were blocked"), because a monotonic upsert can silently drop a second concurrent revision while still reporting ok (the member-removal comment in settings.tsx documents the full failure shape).
- A parity-locked string is changed by updating the surfaces AND the lock needle in `scripts/check-meerkat-parity.mjs` in the same change; grep the script for any user-facing string before editing it. Em dashes are banned by founder rule even in UI copy; the lock needle carried one.
- Guard tests that scan source are the accepted way to pin screen wiring; scope regexes to the exact pattern, count occurrences to pin "all N handlers have it", and pin structural absences (`not.toContain('onPress={() => router.back()}')`).
- Repo idiom: screen logic goes in a pure `data/*-core.ts` with unit tests; every new mobile core needs a `CORE_TWINS` entry or exception line in the parity script in the same change.
- Billing/entitlement truth: mobile `app/(root)/data/app-unlock.ts` + gate in `app/(root)/_layout.tsx`; web `src/lib/hosted-access.ts` + `AppUnlockSection.tsx`. Price never hardcoded ($4.99 one-time + $4.99/mo hosted, founder-locked). A "connection server" is the wss relay; the hosted billing service is `MEERKAT_HOSTED_API_URL` (https); never conflate them in copy.
- Live-testing the web app locally: run Vite with `VITE_MEERKAT_HOSTED_API_URL` pointing at a scratchpad stub answering `GET /api/entitlements/meerkat-app` with `{"unlocked": true}` (CORS `*`), then use the real "Restore purchase" button. Do the age gate + onboarding + restore in ONE uninterrupted session: restarting the dev server mid-boot orphans the web identity's signing key (identity row present, key gone - the exact Set-6 shell bug), and recovering needs an explicit `indexedDB.deleteDatabase` + `localStorage.clear()` + reload (the first wipe can be blocked by the open connection and yields the messageless "Meerkat could not start." once). The iOS Simulator has no tap driver here (no idb); mobile interaction checks are founder device checks.
- A catch that maps every failure to a default state can hide a broken precondition (web unlock validate turns "cannot mint device auth" into a silent LOCKED shell): distinguish precondition failures (surface an error) from the genuine negative result.
- Change-notification seams that skip byte-identical writes fire NO listeners on a re-validate producing the same value; never rely on "the next write will re-trigger it".
- A background persist loop that retries immediately on failure (catch sets dirty, tail-call retries) turns a permanent failure into a silent hot loop with memory-only data (browser-secret-store: 10k identical warns in seconds, secrets lost at reload). Failures need backoff, a retry cap, and an honest surface. Create-if-absent of a shared crypto key must run under the same lock as the writes it protects, or first-boot races mint two keys and orphan the vault.
- `HonestNotice` (mobile kit.tsx) takes `tone: 'info' | 'warning' | 'danger'`; blockers must not use the default green. `markOnboardingComplete` fires listeners synchronously inside the caller's handler.
