## 3. Lessons learned

- **Create-if-absent of a shared crypto key must run under the SAME lock as every write it protects; stamp records with the writing key's id; single-flight PROMISE cache on boot paths.** A read-then-create without a lock mints two keys under concurrency; stamping turns an OperationError into a typed, recoverable half-state.
- **A background persist loop that retries immediately is a hot loop; never clear write-authority state before the write commits.** Exponential backoff + surface threshold + honest banner; snapshot authority per round, restore on failure; a provably-permanent failure is FATAL (surface once, never overwrite the other session); `flush()` must reject on failure; never adopt a stored base over a key with a pending local write.
- **Boot half-states deserve a RECOVERY SCREEN, not an error line;** derive `message || name || String(error)`; render what is lost, what is not, and real options with an AWAITED wipe.
- **One validated state machine, one consumer surface;** checking / verified-yes / verified-no / CANNOT-VERIFY (honest fail-closed + retry); notify on every authoritative answer; adopt in-session answers to stay loop-free.
- **A destructive or creative flow may navigate away ONLY on real success**, and its ERROR must render IN THE PANE THE USER IS LOOKING AT. Set 8's variant: a catch that routes failure copy to a surface BEHIND the open sheet's backdrop is the same bug as an unrendered state - the screen "does nothing". If a sheet stays open for retry, its error belongs inside the sheet, cleared on retype and close.
- **Every mutating flow needs a synchronous single-flight ref; every selection over a filtered list needs stale-selection repair.**
- **Clipboard, share-sheet, pickers, secure store, signing, sealed-decrypt, blob stores, and account flows genuinely throw; claim success only after the await resolves;** a missing API must say so. But verify at the seam first: result-union folds (e.g. `exportThemeBlob` -> null) need no catch, and adding one is noise - Set 8 refuted a "throwing call outside the try" candidate this way.
- **openContent / sealed-decrypt awaits sit INSIDE the try that owns the load state; a dropped result union is a dead tap; try/finally-without-catch is the recurring "tap does nothing" bug.**
- **Navigation, Alerts, and RN modals do not mix in one commit;** queue cross-modal handoffs and flush from `onDismiss` (iOS) + a Platform-gated effect (Android); `return` from a catch so a sheet closes only on real success.
- **Back affordances need `canGoBack()` fallbacks on every deep-linkable screen;** pick the sensible parent per screen.
- **Any async result applied to state needs a supersede guard; auto-timers must be owned and re-verify their target.**
- **Domain rules are swept PER SURFACE and PER ENTRY POINT; predicates re-derive from filtered truth; fail-closed rendering never resurrects disproved affordances.** Set 8: name validation existed on two of three creation entry points; the web scratch path had none.
- **Cross-surface drift hides in half-applied hardening AND in structurally-divergent twins: diff the twin on every find.** The org cores are a documented CORE_TWINS exception, and exactly there the id-minting strategies had drifted (web random UUID, mobile position-based-collidable). An exception to the byte-lock is where drift bugs live; audit exceptions on every sweep of their area.
- **`trim()` is not a visibility check, and "zero-width" is not the whole invisible class.** Bidi controls, hangul fillers (U+3164, U+FFA0, U+115F/U+1160), variation selectors, soft hyphen, braille blank, and the astral tag block all survive both `trim()` and a zero-width-only strip; enumerate the full known invisible set at ONE helper seam. Keep the stored value as typed when real text exists; assert real emoji (ZWJ sequences, VS16) still pass. In RN, avoid `u`-flag `\p{}` escapes (Hermes parse risk that Node-run tests will not catch); use explicit ranges + a surrogate-pair alternation for astral blocks.
- **Ids minted from POSITION collide after delete-then-add; mint against the surviving set (uniqueness loop) or use random ids.** Anything keyed off the id (category assignment, React keys) breaks silently on collision.
- **Fixing a bad local MINT is half a fix when the bad data is SIGNED and replicates: add apply-side tolerance at the shared reader seam.** Descriptors minted by pre-fix code keep arriving over sync forever; the reader (here `communityCategories`) must normalize them (dedupe, first-sorted-wins) so both surfaces heal, and the fix is signature-safe only because canonicalization reads the raw field, never the normalized view. An owner's next save then persists the healed form.
- **Compensating cleanup must sweep EVERYTHING the creation committed, including side-channel writes like change-log records from self-transacted sub-steps.** A purge that deletes rows but not their recorded changes re-ships ghosts on the next session. And the TEST for it must use the REAL recorder: a spy recorder that never persists makes the ghost assertion vacuously green - add a positive control proving the recorder writes what the purge must remove, and revert-check the fix.
- **A control's POSITION is a claim about its behavior.** An add input rendered under a category heading claims it adds into that category; if it adds uncategorized, move it next to the rows it actually appends to. Live walkthroughs catch this class; unit tests cannot.
- **Chain-verification vs cold-start verification are different postures by design:** genesis verifies standalone (id derives from content), revision N verifies against its predecessor OR by owner signature alone (`verifyDescriptorOwnerSignature`) when no predecessor exists locally. Use the right verifier in tests or you will "find" a fake signature bug.
- **Variation matrices beat happy paths for creation-shaped features:** loop the REAL core over every option combination and assert the same invariant set per cell (validity, signatures, rule coverage, honesty counts, rollback). Three of Set 8's five defects (ghost purge, invisible names, category collision) are invisible to any single happy-path test.
- **Transport honesty:** every number shown comes from the engine or sync_ tables ("Waiting · 6 pending" is a real change-log count; "1 member" is the real roster); availability copy never implies always-on; the parity script locks honest state strings (adding new failure copy is free; editing a locked string updates both surfaces + the needle in the same change; a byte-twin file changes identically in BOTH files in the same edit).
- Plan 51 wall holds: account flows never touch the mesh identity; `cannot_verify` never renders as not-entitled.
- **EXPO_PUBLIC / VITE env inlining:** values exist in release bundles only as literal member expressions; captured objects and dynamic keys silently return undefined in production.
- **Programmatic form fills are not user input;** verify input-driven reports with real typing.
- Guard tests that scan source pin screen wiring; every lock must fail on revert FOR THE RIGHT REASON (revert-check new locks). Screen logic goes in a pure `data/*-core.ts` with a CORE_TWINS entry or documented exception. Em dashes are banned even in UI copy.
- Billing/entitlement truth: web `lib/hosted-access.ts` + provider `appUnlock` machine; mobile `data/app-unlock.ts` + the root gate. Price never hardcoded ($4.99 one-time + $4.99/mo hosted, founder-locked). A "connection server" is the wss relay; the hosted billing service is `MEERKAT_HOSTED_API_URL`; never conflate them.
- Live-testing recipe: Vite :5199 + scratchpad entitlement stub :8799 (`GET /api/entitlements/meerkat-app` -> `{"unlocked":true}`, CORS `*`), real "Restore purchase" if state was wiped; prior-state sessions skip onboarding; close stale tabs; AWAIT wipes; never click `window.confirm`/`alert` in automation; call `read_console_messages` EARLY (tracking starts on first call); `file_upload` targets the hidden file input; kill servers when done (targeted `kill <pid>` of your own background PIDs). The iOS Simulator has no tap driver; mobile interaction checks are founder device checks.
- `HonestNotice` (mobile) takes `tone`; blockers must not use the default green. `CopyRow` has no built-in copied feedback. `markOnboardingComplete` fires listeners synchronously.
