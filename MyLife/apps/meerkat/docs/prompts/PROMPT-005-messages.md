## 3. Lessons learned

- **EXPO_PUBLIC inlining contract:** an `EXPO_PUBLIC_*` value exists in a release bundle only where the source contains the literal member expression `process.env.EXPO_PUBLIC_NAME`. Captured objects, destructuring, and dynamic keys silently return undefined in TestFlight/production while working in dev, Expo Go, and Vitest. Check this first for any "works locally, unconfigured in TestFlight" symptom. Web (Vite) has the same rule with `import.meta.env.VITE_*`.
- **Navigation and RN modals do not mix in one commit.** Never unmount a visible RN `<Modal>` (toggle `visible`), never navigate imperatively, present a second Modal, or fire an `Alert.alert` while one is dismissing. The accepted fix shape: queue the action in a ref, flush from Modal `onDismiss` (iOS-only in RN 0.81) plus a Platform-gated visibility effect (Android unmounts Modal children the instant visible flips false). The queue must live in a component that SURVIVES the dismissal; when a shared sheet's callbacks may alert/navigate, put the queue INSIDE the sheet (MessageActionsSheet shape); when the host owns the Modal, the host owns the queue. NEW: the navigation can hide inside a PROVIDER - `startCall` pushes `/call` synchronously before its first await, so `closeSheet(); void startCall(...)` is a close-then-navigate even though no `router.` appears at the call site; audit what a provider method does before its first await. Also keep the last content rendered during dismissal (`displaySelected = selected ?? lastRef.current`) so the sheet does not blank mid-animation. Sweep pattern: grep every `<Modal` screen for `setXOpen(false)` adjacent to `router.`/`Alert.alert`/another `setYOpen(true)`, plus conditional mounts `{show ? <Sheet visible`.
- **try/finally without catch is the recurring "tap does nothing" bug, and it clusters in file/blob pipelines.** `finally` resets busy while the rejection vanishes; an await BEFORE the try (or before busy is set - add-friend's relay re-probe) skips the finally and strands the busy label or dead-taps silently. Every async handler needs a catch that renders an honest failure; awaits belong INSIDE the try and busy window; batch loops catch per item; a `void promise` without `.catch` is the same bug in a different jacket - even when a comment says "best-effort". Verify the deep seam: provider methods that LOOK result-union can still throw (`createDmGroup`/`queueDmShred`/`dmGroup*` all await `ensureEffectiveRelayUrl` + crypto cores). Conversely, verify before adding noise: CallSession's accept/decline/hangup/toggle genuinely CANNOT reject (all sends fold to boolean internally), so bare `void acceptCall()` is correct there.
- **A dropped result union is the same dead tap as a swallowed rejection.** `void startCall(...)` discards `{ok:false, reason}` that the API deliberately returns; every caller must render the union. When several surfaces need the same failure copy, single-source it in a CORE_TWIN helper with a surface parameter (`startCallFailureCopy(reason, 'app'|'browser')`) instead of duplicating inline maps that drift.
- **A "pure resolver" helper with try/finally still propagates; make it fail-safe when null is its honest miss** (canvas-assets shape), and lock the catch COUNT when a file has several such blocks.
- Success copy ("Copied", "Sent", "Saved") is claimed only AFTER the await that makes it true resolves. A silent success is the inverse bug: a real write (call report) with NO feedback invites hammering and duplicate rows - confirm, record once, flip the control to a done state.
- **Domain rules must be swept PER SURFACE and PER ENTRY POINT, and "read-only" means EVERY write verb INCLUDING external intake.** After Set 3 locked archived channels across chat/post/reaction/room surfaces, the share-inbox pickers still offered archived channels as ROUTE TARGETS on both surfaces. Enumerate pickers, intake flows, deep links, and forwarding paths as write entry points too; filter at the offer stage (never list a target the route would reject) and keep a stale-selection repair so a target archived after selection self-repairs. AND: when an offer-stage filter lands, RE-DERIVE every enable/disable predicate from the FILTERED truth - filtering made "communities exist but zero routable targets" reachable, and a button still enabled off the unfiltered count becomes a misleading-error tap (mobile) while its twin disables (web).
- **Error surfaces must live in the pane the user is looking at**; every visible segment needs its own honest failure surface for shared error state (`display:none` siblings hide failures).
- Back affordances need `router.canGoBack()` with a fallback on EVERY deep-linkable screen; fall back to the nearest sensible parent (messages for a DM thread/calls list, calls history for the active call, this MODE's entry screen for a dual-entry ceremony screen - derive the fallback from the route param when one screen serves two flows).
- **Controls must toggle off observed state, never hardcode the "on" direction**; derive next from reduced truth, catch permission-denial rejections, label from real state.
- When one row has several action buttons sharing a flow, busy needs a per-action dimension; and any create-flow needs a synchronous re-entry ref so two fast taps cannot mint two entities (groups, retries).
- Cross-surface drift hides in half-applied hardening: diff the twin the moment you find a bug once (delete-confirm, draft stash before; failure copy, Leave-group, stale-target repair this time). A whole FEATURE on one surface (web Leave group) is the same drift one level up.
- Fail-closed rendering: an error state must not resurrect affordances the failure just proved impossible; selection/PICK state must self-repair when its referent disappears - including per-open reset of sheet-local picks so stale selections cannot ride into the next submit.
- Multi-step sequential mutations over a device list need single-flight + a partial-failure notice.
- A parity-locked string changes by updating the surfaces AND the lock needle in `scripts/check-meerkat-parity.mjs` in the same change; ADDING a locked string to a new surface is free. Em dashes are banned even in UI copy.
- Guard tests that scan source are the accepted way to pin screen wiring: scope regexes to the exact pattern, count occurrences to pin "all N handlers have it", and pin structural absences (`not.toContain('void startCall(')`).
- Repo idiom: screen logic goes in a pure `data/*-core.ts` with unit tests; every new mobile core needs a `CORE_TWINS` entry or exception line in the parity script in the same change. EXTENDING an existing null-anchor core twin (whole-file compare) is the cheapest way to add shared logic: edit both files byte-identically, no script change needed.
- Billing/entitlement truth: mobile `data/app-unlock.ts` + gate in `(root)/_layout.tsx`; web `lib/hosted-access.ts` + `AppUnlockSection.tsx`. Price never hardcoded ($4.99 one-time + $4.99/mo hosted, founder-locked). A "connection server" is the wss relay; the hosted billing service is `MEERKAT_HOSTED_API_URL` (https); never conflate them in copy.
- Live-testing the web app locally: Vite on :5199 with `VITE_MEERKAT_HOSTED_API_URL` at a scratchpad stub answering `GET /api/entitlements/meerkat-app` `{"unlocked": true}` (CORS `*`), then the real "Restore purchase". Do age gate + onboarding + restore in ONE uninterrupted session; keep default name values (password-manager popups steal focus); never click window.confirm/alert paths during automation - source-lock those. NEW: close STALE app tabs from earlier sessions before wiping site data - a second live tab holds the old vault key and re-triggers the browser-secret-store mint race; staging a share for picker tests works headlessly by setting the hidden `input[type=file]`'s files via DataTransfer and dispatching `change` (synthetic drop events do not reach the React handler). The iOS Simulator has no tap driver; mobile interaction checks are founder device checks.
- A background persist loop that retries immediately on failure turns a permanent failure into a silent hot loop with memory-only data; failures need backoff, a cap, and an honest surface; create-if-absent of a shared crypto key must run under the same lock as the writes it protects.
- A catch that maps every failure to a default state can hide a broken precondition; distinguish precondition failures (surface an error) from a genuine negative result. Change-notification seams that skip byte-identical writes fire NO listeners on a re-validate producing the same value.
- `HonestNotice` (mobile kit.tsx) takes `tone: 'info' | 'warning' | 'danger'`; blockers must not use the default green. `markOnboardingComplete` fires listeners synchronously inside the caller's handler.
