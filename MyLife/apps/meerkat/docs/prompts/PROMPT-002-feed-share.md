## 3. Lessons learned

- **EXPO_PUBLIC inlining contract:** an `EXPO_PUBLIC_*` value exists in a release bundle only where the source contains the literal member expression `process.env.EXPO_PUBLIC_NAME`. Captured objects, destructuring, and dynamic keys silently return undefined in TestFlight/production while working in dev, Expo Go, and Vitest. Check this first for any "works locally, unconfigured in TestFlight" symptom. Web (Vite) has the same rule with `import.meta.env.VITE_*`.
- **Navigation and RN modals do not mix in one commit.** Never unmount a visible RN `<Modal>` (toggle `visible`), never navigate imperatively or present a second Modal while one is dismissing, and never guard a route by returning `<Redirect>` in place of a layout's own `<Stack>`. The accepted fix shape: queue the action in state, flush it from Modal `onDismiss` (iOS) plus a Platform-gated visibility effect (Android). This class is not confined to gates: ANY screen where closing a sheet leads somewhere (status links, sheet-to-sheet handoffs) carries it. Sweep pattern: grep for `setXOpen(false)` or `setItem(null)` adjacent to `router.` or another `setYOpen(true)`.
- **try/finally without catch is the recurring "tap does nothing" bug.** `finally` resets busy so the UI looks idle while the rejection vanished silently. Every async screen handler needs a catch that renders an honest failure; better, move the flow into a pure `data/*` function that catches internally and returns a result union (`runOpenLinkFlow` pattern), then unit-test the flow instead of the screen. The other "tap does nothing" cause is a stale native modal window eating touches (see above); a whole-app freeze points to the second.
- Success copy ("Copied", "Sent", "Saved") is claimed only AFTER the await that makes it true resolves. Never set it before or alongside the await.
- Back affordances need `router.canGoBack()` with a fallback route whenever the screen can be the stack's only entry: entitlement-gate replaces, OS-share deep links (ShareIntakeWatcher pushes `/share-inbox`), and relaunch restores all create that state. A locked-state fallback must target a FREE route.
- Fail-closed rendering: an error state must not resurrect affordances the failure just proved impossible, and a picker must not offer destinations that can only fail (gate channel/files on having a community, DM on an eligible friend). Key any "you need X first" notice on what is actually offered, or it lies to users holding a different live option.
- Selection state (send target, destination, recipient) must self-repair when its referent disappears. A "default only when null" effect leaves stale targets pointing at deleted communities/channels.
- When one row has several action buttons, busy state needs a per-action dimension (`{ id, action }`), or every button on the row claims the in-flight verb.
- Cross-surface tap rules (heart add-vs-remove) must come from the one shared core (`resolveReactionTap`); an inline re-implementation on one surface is silent drift.
- Billing/entitlement truth: mobile `app/(root)/data/app-unlock.ts` (sole importer of react-native-purchases; unlock derived only from store CustomerInfo), gate in `app/(root)/_layout.tsx`; web `src/lib/hosted-access.ts` + `AppUnlockSection.tsx`. Price never hardcoded. `check-build-env.mjs` enforces store keys/https endpoints only for the production EAS profile; testflight may legitimately lack hosted endpoints and runtime copy must stay honest about it. A "connection server" is the wss relay; the hosted billing/link service is `MEERKAT_HOSTED_API_URL` (https); copy must not conflate them. Web checkout is redirect-shaped: consume `success_url` params on return, confirm server-side, strip from the URL; the param is never an entitlement.
- `markOnboardingComplete` fires listeners SYNCHRONOUSLY inside the caller's handler; every subscriber re-renders in the same commit as whatever the caller does next.
- `HonestNotice` (mobile kit.tsx) takes `tone: 'info' | 'warning' | 'danger'`; blockers must not use the default green.
- Repo idiom: screen logic goes in a pure `data/*-core.ts` (or an existing pure seam like `remote-share.ts`) with unit tests; every new mobile `data/*-core.ts` needs a `CORE_TWINS` entry or `CORE_TWIN_EXCEPTIONS` line in `scripts/check-meerkat-parity.mjs` in the same change. `feed-view-core.ts` is an anchored twin (mobile and web must match line-for-line below `export const HEART_EMOJI`); edit both together.
- Always grep `scripts/check-meerkat-parity.mjs` for a string before changing it; Share Inbox honesty anchors (`isShareIntakeSent`, the dm-surface import, `shareTargetSupported ?`) and many public-layer strings are locked.
- Guard tests that scan source are the accepted way to pin screen wiring with no render harness. Scope regexes to the exact pattern; to pin "both handlers have it", count occurrences (`source.match(/.../gu)?.length`) instead of a broad regex.
- Live-testing the web app locally: run Vite with `VITE_MEERKAT_HOSTED_API_URL` pointing at a scratchpad stub that answers `GET /api/entitlements/meerkat-app` with `{ "unlocked": true, ... }` (CORS `*`), then use the real "Restore purchase" button; seeding `meerkat_app_unlock_state` in localStorage alone is correctly rejected because App.tsx re-validates against the API and fails closed. The founder's Chrome is SHARED across concurrent agents: use `isolatedContext` pages, expect resets that wipe them mid-flow, and treat any in-page state as disposable. The iOS Simulator has no tap driver here (no idb); mobile interaction checks are founder device checks.
- A catch that maps every failure to a default state can hide a broken precondition: App.tsx's unlock validate turns "cannot mint device auth" into a silent LOCKED shell (section 2 item 7). When catching around a multi-step await, distinguish precondition failures (surface an error) from the genuine negative result (render the honest default).
- When hardening a file's async handlers, sweep the WHOLE file for uncaught awaits, including mount/boot effects, not just tap handlers: the ShareInbox boot drain (issue 14) sat one line above two handlers the same session had just fixed.
- A catch that returns early without rendering anything just converts an unhandled rejection into a quieter dead tap. The catch must set visible state ("Could not copy"), matching whatever the other surface already says for the same failure.
- Change-notification seams that skip byte-identical writes (`setCachedAppUnlock`) mean a re-validate that produces the same value fires NO listeners; never rely on "the next write will re-trigger it" to recover from a failed first validate.
